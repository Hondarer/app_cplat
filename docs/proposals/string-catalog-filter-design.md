# 文字列カタログの条件式フィルターの設計

> [!NOTE]
> 本書は、文字列カタログの条件式フィルターの採用済み設計と、追加機能の提案を記録します。  
> 現行仕様については、[文字列カタログの機能仕様](../functional-spec/string_catalog.md) および公開ヘッダー [filter.h](../../prod/include/cplat/string_catalog/filter.h) を参照してください。

## 目的

本設計は、トレース ログの出力詳細度を、プロセスの実行中に随時変更する機能を提供します。  
通常時の詳細度はトレースの出力先ごとのしきい値で決め、条件式に一致した文字列だけを、しきい値によらず出力する強制出力へ引き上げます。  
一致するかどうかは、文字列カタログの項目情報と引数の値を条件式で判定して決定します。

判定条件は、条件式を 1 行に 1 つずつ記載した条件式リストとして与えます。  
条件式リストは、外部ファイルなどで管理し、一部の行を編集してからプロセスへ再読み込みさせる運用を主な利用方法とします。  
個別の行の追加、更新、削除にも対応しますが、利用頻度は低いと想定します。

フィルター機能への入力は、`char[N][M]` のような固定長文字列の配列です。  
ファイルの読み込みと配列への格納は利用側が行います。

条件式リストをコンパイルする機能と、コンパイル結果を使用して判定する機能は分離します。  
コンパイル結果であるフィルター オブジェクトは、行数と行幅から大きさが一意に決定される固定長のデータ構造とします。  
固定長かつポインターを含まない構造とすることで、フィルター オブジェクトをバイナリ イメージとして扱えます。

本設計では、次の要件を同時に満たすことを目標とします。

- 文字列キー、ID、分類値、および引数の値を条件式の対象として参照できること
- 数値の比較と範囲判定、文字列の完全一致、先頭一致、終端一致、部分一致 (中間一致) を判定できること
- 1 行の中で、判定条件を AND、OR、NOT、および括弧によって組み合わせられること
- 条件式リストのいずれかの行に一致したかどうかを、組み立てた文字列とともに利用側へ返すこと
- フィルター オブジェクトの大きさが、条件式リストの行数と行幅だけから決定されること
- フィルター オブジェクトがポインターを含まず、バイナリ イメージとして保存、複製、転送できること
- コンパイル処理が、カタログ定義にも実行中の判定処理にも依存せず、単独で実行できること
- 条件式リストを、トレースの出力を停止させずに差し替えられること
- 差し替え時に、変更していない行の名前解決と事前計算を再利用し、変更した行だけを計算すること
- 不正な行があっても、その行だけを無効にし、他の行を適用すること
- 判定に引数の値を必要としない文字列に対しては、判定のための可変長引数の取得 (収集) を行わないこと
- フィルター オブジェクトから条件式リストを復元 (デコンパイル) できること
- カタログ定義を参照できる場合に、条件の内容を自然文で表現できること
- 差し替え時の内部バッファーの整合性確保を、利用側から隠蔽すること
- `string_catalog` から `trace` モジュールへの直接依存を排除し、疎結合を維持すること

## 適用範囲

本設計の対象範囲は、条件式と条件式リストの構文仕様、条件式リストのコンパイル、フィルター オブジェクトのデータ構造、カタログ定義への関連付け、判定処理の評価規則、実行中のフィルター オブジェクトの差し替え、フィルター オブジェクトのデコンパイルと自然文での表現、および判定と書式展開を一体化した公開 API です。

次の事項は、本設計の対象外とします。

- 言語別の書式定義および備考を対象とした判定
- 組み立て後の文字列を対象とした判定 (出力言語によって文面が変化し、同一条件で再現性のある結果を得られないため)
- 条件式リストを格納するファイルのデータ形式、ファイルの読み込み、および変更の検出 (利用側の責務とするため)
- トレース出力先の振り分け、および分類値からトレース レベルへのマッピング (利用側およびトレース基盤の責務とするため)
- フィルター オブジェクトのバイナリ イメージを、異なるバイト順序または異なる形式版の環境へ持ち込むための変換

## アーキテクチャーと判定層の選定

判定処理は、`string_catalog` の層において、書式を展開する前の値に対して実行します。

トレーサーのフック関数 `cplat_tracer_hook_fn` が受け取るのは、組み立て済みのメッセージ文字列のみです。  
フックの段階では、文字列キーや引数の値を型情報とともに取得できません。  
また、フックの段階ではトレース レベルが確定しており、判定結果によって強制出力へ引き上げられません。

`string_catalog` の内部処理では、`cplat_internal_string_catalog_collect_arguments()` が可変長引数を型付き構造体の配列 `cplat_internal_string_catalog_argument_value` へ抽出した後に書式を展開します。  
条件式の判定はこの配列を入力として実行するため、引数のデータ型に応じた比較を行えます。

C 言語の可変長引数 (`va_list`) は 1 回しか走査できません。  
そのため、判定処理と書式展開処理を単一の API にまとめ、抽出した引数値の配列を判定と展開の間で共有します。  
この方式は `va_copy` に依存しないため、Linux/GCC と Windows/MSVC の双方で同一の実装を維持できます。

`trace` モジュールとの連携は利用側の責務とします。  
分類値 (`category`) をトレース レベルとして解釈するかどうかは利用側の規約であり、`string_catalog` 自体は分類値を解釈しない現行の方針を維持します。

## 条件式の仕様

### 参照可能なフィールド

条件式では、次のフィールドを参照できます。

| フィールド | 値の型 | 説明 |
|---|---|---|
| `key` | 整数 | 文字列キー。整数の定数、または名前解決テーブルで解決した列挙定数名との比較対象 |
| `id` | 文字列 | 項目の ID。未設定の場合は NULL |
| `category` | 整数 | 分類値 |
| `arg.<name>` | 引数の型に従う | 引数名で指定した引数の値 |
| `arg[<n>]` | 引数の型に従う | 0 起点のインデックスで指定した引数の値 |

Table: フィルター条件式で参照可能なフィールド一覧

`id` は運用補助用の補足文字列です。  
絞り込みの入力条件として参照することは許可しますが、カタログ内部での項目識別や処理分岐には使用しません。

引数はカタログの項目ごとに名前、インデックス、データ型が異なります。  
項目に対応する引数が定義されていない場合、その引数を参照する比較式は偽として評価されます。  
引数が定義されているかどうかを明示的に判定する場合は、`has(arg.<name>)` を使用します。

### 判定演算子

数値フィールドに対しては、次の判定演算子を使用できます。

| 構文 | 意味 |
|---|---|
| `==` `!=` | 等しい、等しくない |
| `<` `<=` `>` `>=` | 大小の比較 |
| `in [a, b, ...]` | 列挙した値のいずれかと等しい |
| `between a and b` | `a` 以上かつ `b` 以下 |

Table: 数値フィールドに対する判定演算子

文字列フィールドに対しては、次の判定演算子を使用できます。

| 構文 | 意味 |
|---|---|
| `==` `!=` | 完全一致、不一致 |
| `starts_with` | 先頭一致 |
| `ends_with` | 終端一致 |
| `contains` | 部分一致 (中間一致) |
| `in [a, b, ...]` | 列挙した文字列のいずれかと完全一致 |
| `matches` | 正規表現に一致する部分を含む |

Table: 文字列フィールドに対する判定演算子

文字列の判定には、ASCII の大文字と小文字を区別しないバリアント (`starts_with_i` など) を提供します。  
大文字と小文字を区別しない比較は ASCII 文字の範囲に限定し、実行時ロケールに依存させません。  
ASCII 以外のバイト列はそのままバイト単位で比較します。  
UTF-8 の正規化は行いません。

`id`、STRING 型の引数、および POINTER 型の引数は、`== null` および `!= null` によって NULL であるかを判定できます。  
対象が NULL の場合、`starts_with` などの文字列判定演算はすべて偽として評価されます。

#### 正規表現による一致判定

`matches` は、文字列のどこかに正規表現が一致すれば真とする部分一致です。  
全体を対象とする場合は、`^` と `$` で位置を固定します (例: `arg.job_name matches "^import-[0-9]+$"`)。  
`matches_i` は、ASCII の大文字と小文字を区別しないバリアントです。  
対象は `id` と STRING 型の引数で、パターンは文字列の字句で 1 個だけ書きます。

正規表現の方言は、`cplat_regex` の既定である ECMAScript です。  
条件式の変換の時点でパターンを一度コンパイルして構文を確かめ、誤りがある行は原因を正規表現の誤りとして無効にします。  
フィルター オブジェクトはポインターを含まないため、コンパイルした正規表現は保持せず、パターンの文字列と行内の番号だけを格納します。  
スロットは、適用のたびに面ごとにパターンをコンパイルし直して保持します。  
`id` に対するパターンは、他の判定要素と同じく適用の時点で項目ごとに結果が確定します。

| 制限 | 値と理由 |
|---|---|
| 1 行のパターンの数 | 4 個以下。面ごとに保持する正規表現の数を抑えるためです |
| 照合する文字列の長さ | 512 バイト以下。超える文字列は照合せず偽とします。照合がバックトラッキングで行われ、長い文字列と複雑なパターンの組み合わせで時間とスタックを消費するためです |

Table: 正規表現による一致判定の制限

`cplat_regex` は照合のたびにメモリを確保します。  
このため、`matches` と `matches_i` を含む行に限り、変換、適用、判定の間にメモリを確保します。  
照合でメモリ不足や不正な UTF-8 を検出した場合、その判定要素は偽として扱い、トレースの出力は止めません。

正規表現の演算子は、フィルター オブジェクトの形式版を変えずに追加しました。  
これより前の版のライブラリは、`matches` を含むフィルター オブジェクトだけを、未知の演算子を含むとして拒否します。

### 引数のデータ型と比較規則

引数のデータ型は、比較処理のために次の 5 つの型区分へ分類します。

| 型区分 | 対象の引数型 |
|---|---|
| 符号付き整数 | INT8、INT16、INT32、INT64、SSIZE、ERROR_CODE、CHAR |
| 符号なし整数 | UINT8、UINT16、UINT32、UINT64、HEX8、HEX16、HEX32、HEX64、SIZE |
| 浮動小数点数 | DOUBLE |
| 文字列 | STRING |
| ポインター | POINTER |

Table: フィルター条件式における引数データ型の区分

符号付き整数と符号なし整数の比較は、C 言語の暗黙の型変換規則ではなく、数学的な大小関係に基づいて判定します。  
たとえば、INT32 の `-1` と整数の定数 `4294967295` を比較した場合、等しいとは判定されません。

浮動小数点数と整数の定数を比較する場合は、整数の定数を倍精度浮動小数点数へ変換して比較します。  
値が NaN の場合、`!=` は真となり、それ以外の比較演算はすべて偽となります。

ポインターは、アドレスを符号なし整数値として比較します。  
アドレス値は実行ごとに変動するため、主な用途は NULL の判定です。

引数の型区分と判定演算子が一致しない場合、その項目における判定結果は偽となります。  
たとえば、STRING 型の引数に対して `<` を適用した場合などが該当します。  
項目に対応する引数が無い場合も、その引数を参照する判定要素は偽となります (`has` を除く)。

偽となるのは判定要素であり、行ではありません。  
判定要素を評価の対象から外すのではなく、偽の値として論理演算へ渡します。  
`!=` も判定要素の 1 つであるため、型が合わない場合は偽となります。  
一方、`!` は偽の判定要素を否定して真にします。

| 条件式 | `v` が STRING の項目での結果 |
|---|---|
| `arg.v == 5` | 偽 |
| `arg.v != 5` | 偽 |
| `!(arg.v == 5)` | 真 |
| `arg.v == 5 \|\| arg.v starts_with "E"` | 右辺の結果 |

Table: 型が合わない判定要素を含む条件式の判定結果

同名の引数が項目によって数値と文字列に分かれる場合、`!=` と `!(==)` が逆の結果になるなど、利用者の期待と判定結果がずれることがあります。  
この不一致を条件式の作成時に知らせる手段は、「型が合わない比較要素を条件式の作成時に通知する」で扱います。  
カタログへの関連付けの時点で、事前計算ですべての項目が「常に不一致」となる行を診断情報として通知します。

### 論理演算

1 行の条件式の中では、各判定要素を `&&`、`||`、`!`、および括弧を用いて組み合わせられます。  
演算子の優先順位は `!`、`&&`、`||` の順に高くなります。

論理式の評価は左から右へ短絡評価 (ショート サーキット) で実行します。  
`&&` の左辺が偽の場合、または `||` の左辺が真の場合は、右辺を評価しません。

### 構文規則

1 行の条件式の構文規則は次のとおりです。

```text
expression   = or_expr ;
or_expr      = and_expr , { "||" , and_expr } ;
and_expr     = unary_expr , { "&&" , unary_expr } ;
unary_expr   = "!" , unary_expr | primary ;
primary      = "(" , expression , ")" | predicate ;
predicate    = field , compare_op , literal
             | field , string_op , string
             | field , "in" , "[" , literal , { "," , literal } , "]"
             | field , "between" , literal , "and" , literal
             | "has" , "(" , argument_ref , ")" ;
field        = "key" | "id" | "category" | argument_ref ;
argument_ref = "arg" , "." , identifier | "arg" , "[" , decimal , "]" ;
compare_op   = "==" | "!=" | "<" | "<=" | ">" | ">=" ;
string_op    = "starts_with" | "ends_with" | "contains"
             | "starts_with_i" | "ends_with_i" | "contains_i"
             | "matches" | "matches_i" ;
literal      = integer | float | string | character | "null" | identifier ;
```

字句の定義は次のとおりです。

- 整数は、符号付き 10 進数、または `0x` で始まる 16 進数です。  
  64 ビット整数の範囲を超える値は構文エラーとして扱います。
- 浮動小数点数は、小数点または指数部を含む 10 進数です。
- 文字列は二重引用符 (`"`) で囲み、`\"`、`\\`、`\n`、`\t`、`\xHH` のエスケープ シーケンスを使用できます。
- 文字は単一引用符 (`'`) で囲んだ 1 文字であり、CHAR 型の引数と比較します。
- 識別子は、英字またはアンダースコア (`_`) で始まり、英数字と `_` が続く文字列です。  
  `literal` に指定された識別子は、文字列キーの名前解決テーブルを参照して整数値へ解決します。

判定要素数と括弧のネスト深度には上限を設けます。  
構文解析時の再帰深度と、確保する内部メモリ量を一定範囲に抑えるためです。  
上限値は実装時に決定し、公開ヘッダーの定数として定義します。

## 条件式リストの仕様

### 入力の形式

条件式リストは、固定長の文字列を並べた配列として受け取ります。  
関数には、配列の先頭アドレス、行数、1 行あたりのバイト数 (行幅) を渡します。  
`char lines[N][M]` の場合、行数は `N`、行幅は `M` です。

各行は、最初の NUL 文字、または行幅の末尾のどちらか早い位置で終了します。  
行幅いっぱいまで文字が格納された行は、NUL 文字で終端していなくても受け付けます。  
1 つの条件式を複数の行へ分割することはできません。  
条件式の最大長は行幅によって決定されます。

各行の先頭と末尾の空白は無視します。  
空白だけの行と、先頭が `#` の行は、判定に使用しない行として扱います。  
コメントや、一時的に無効にした条件を、行の位置を保ったまま記載するためです。

### 行の結合規則

条件式リストの判定結果は、有効なすべての行の論理和です。  
文字列は、いずれかの行の条件式に一致した場合に一致と判定されます。  
行の順序は判定結果に影響しません。

有効な行が 1 つも存在しない場合、どの文字列も一致しません。  
この状態では強制出力へ引き上げる文字列がなく、トレースは出力先ごとのしきい値に従って出力されます。  
特定の文字列を一致の対象から外す条件は、同じ行の中で `!` を用いて記載します。

出力詳細度を制御する条件式リストの例は次のとおりです。

```text
# 調査中の障害: 設定ファイルの読み込みに関する文字列を、分類値によらず出力します。
key == SAMPLE_MESSAGES_KEY_FILE_OPEN_FAILED && arg.file_path starts_with "/etc/"

# 一時的に無効にした条件
# category <= 5
```

基本の詳細度は出力先のしきい値で決め、調査のために詳細度を上げる条件を行として追加する運用を想定しています。  
調査が終了した行は、削除するか先頭に `#` を付与して無効にします。

### 不正な行の扱い

不正な行は、その行だけを無効にします。  
他の有効な行は適用します。  
運用中の編集ミスによって、他の条件まで無効になることを避けるためです。

不正な行は、次の 2 つの段階で検出します。

| 段階 | 検出する内容 |
|---|---|
| コンパイル | 構文と字句のエラー、フィールド・演算子・定数の型の組み合わせの誤り、各種上限の超過、および正規表現の構文の誤り |
| 適用 | 解決できない文字列キー・分類値・引数の名前、分類値の名前の範囲外の定数、コンパイルできない正規表現、および事前計算ですべての項目が「常に不一致」となる条件 |

Table: フィルター条件式の不正な行を検出する段階と内容

無効にした行は、行番号、行内の位置、および原因を診断情報として利用側へ返します。  
利用側は、診断情報をトレースへ出力するなどして、編集ミスを検出できます。

コンパイルで無効にした行、空行、およびコメント行は、フィルター オブジェクトへ格納しません。  
フィルター オブジェクトが保持するのは、コンパイルに成功した条件式だけです。

そのため、フィルター オブジェクト内の行番号は、入力した条件式リストの行番号と一致しません。  
入力した条件式リストの行番号は、診断情報だけが保持します。

## 処理の分離

処理は、次の 2 つの段階に分離します。

| 段階 | 入力 | 出力 | カタログ定義への依存 |
|---|---|---|---|
| コンパイル | 条件式リスト (固定長文字列の配列) | フィルター オブジェクト | なし |
| 適用と判定 | フィルター オブジェクト | 判定結果と組み立てた文字列 | あり |

コンパイルは、構文解析と命令列の生成だけを行います。  
カタログ定義を参照しないため、対象のカタログを持たない管理ツールや別のプロセスでも実行できます。

カタログ定義への関連付け (引数名のインデックス解決、型チェック、判定の事前計算) は、フィルター オブジェクトをフィルター スロットへ適用する時点で行います。  
フィルター スロットは、カタログ定義と結び付いた実行時のオブジェクトであり、判定処理の入口です。

## フィルター オブジェクト

### データ構造

フィルター オブジェクトは、次の要素を並べた固定長のデータ構造です。

| 要素 | 内容 |
|---|---|
| ヘッダー | 識別用の署名、形式版、バイト順序の目印、行数の上限、行幅、格納している条件式の数、全体のバイト数 |
| 行レコードの配列 | 行数の上限と同じ数のレコード (各レコードの大きさは同一) |

Table: フィルター オブジェクト全体のデータ構造要素

先頭から、格納している条件式の数までのレコードが有効です。  
それ以降のレコードは未使用です。

行レコードは、次の要素で構成します。

| 要素 | 内容 |
|---|---|
| 行の内容のハッシュ値 | 差し替え時における未変更行の識別用ハッシュ値 |
| 命令数と定数領域の使用量 | 領域のうち、実際に使用している範囲 |
| 命令領域 | 後置記法の命令列の格納領域 |
| 定数領域 | 文字列定数、数値定数、引数名、および文字列キーの名前の格納領域 |

Table: フィルター オブジェクト行レコードの構成要素

命令のオペランドは、定数領域の先頭からのバイト単位のオフセットで表します。  
ポインターを含めないため、フィルター オブジェクトはどのアドレスへ配置しても解釈できます。

数値定数には、入力での記法 (10 進数または 16 進数) を表す情報を添えます。  
デコンパイルで、入力した記法のまま復元するためです。

### 大きさの算出

フィルター オブジェクトのバイト数は、行数の上限 `N` と行幅 `M` だけから決定されます。

```text
行レコード長(M) = 16 + 8 × M + 8 × M = 16 + 16 × M
フィルター オブジェクト長(N, M) = 64 + N × (16 + 16 × M)
ソース領域長(N, M) = 64 + フィルター オブジェクト長(N, M)
```

領域長の算出式は決定済みです。  
命令領域と定数領域は、それぞれ行幅 `M` の 8 倍のバイト数とします。  
8 バイトの命令を行幅と同じ個数まで格納でき、定数は行幅の 8 倍の領域内に格納します。

公開ヘッダーでは、この算出をマクロとして提供します。  
利用側は、静的な配列または利用側が確保した領域を、フィルター オブジェクトの格納先として使用できます。

```c
static unsigned char image[CPLAT_STRING_CATALOG_FILTER_IMAGE_SIZE(64, 256)];
```

### バイナリ イメージとしての扱い

フィルター オブジェクトはポインターを含まず、全体が連続した領域に収まります。  
そのため、ファイルへの保存、共有メモリへの配置、プロセス間の転送、および `memcpy` による複製を行えます。

同じ形式版、同じバイト順序、同じ実装であれば、別のプロセスでコンパイルしたフィルター オブジェクトをそのまま適用できます。  
異なるバイト順序の環境へ持ち込む場合の変換は、本設計の対象外とします。

フィルター オブジェクトは、外部から与えられるデータとして扱います。  
適用の時点で、署名、形式版、バイト順序の目印、行数、行幅、全体のバイト数、および命令とオペランドの参照先が領域内に収まることを検証します。  
検証に失敗した場合は適用せず、現在の内容を維持します。

### 行単位の編集

行レコードは同じ大きさであるため、行番号を指定した編集を、フィルター オブジェクトに対して直接行えます。  
ここでの行番号は、フィルター オブジェクトが格納している条件式の並び順です。

- 行の更新は、対象のレコードだけを再生成します。
- 行の挿入と削除は、後続のレコードを移動します。
- 編集した行だけを再コンパイルすればよく、リスト全体の再コンパイルは不要です。

## カタログ定義への関連付けと判定

### 適用時の処理

フィルター オブジェクトをフィルター スロットへ適用する時点で、次の処理を行います。

1. フィルター オブジェクトの検証を行います。
2. 各行の文字列キーの名前を、名前解決テーブルによって整数値へ解決します。
3. 各行の引数名を、カタログの項目ごとのインデックスへ解決します。
4. 各行と各項目の組について、判定結果を事前計算します。
5. 行ごとの結果を項目ごとに集約し、判定処理から参照される内容と入れ替えます。

文字列キーの列挙定数名そのものは、実行時のカタログ データ構造には格納されていません。  
名前解決テーブルは、フィルター スロットの作成時に渡します。  
名前解決テーブルは、カタログ定義生成器が `<module>_key_names()` として自動出力します。  
名前解決テーブルを渡さない場合、条件式内で指定できる文字列キーは整数の定数値のみとなります。

この方式では既存の `cplat_string_catalog_entry` 構造体にメンバーを追加しないため、メモリ レイアウトを維持できます。

列挙定数の値はカタログ定義の並び順に基づいて割り当てられるため、定義順の変更によって値が変動する可能性があります。  
条件式リストは外部ファイルで管理するため、文字列キーは整数値ではなく列挙定数名で記述することを推奨します。

名前を解決できない行、および事前計算ですべての項目が「常に不一致」となる行は、その行だけを無効にします。  
一部の項目で比較の型が合わない場合は、その項目の比較要素を偽として扱い、行は有効なままです。  
引数値に依存する比較要素は不定として事前計算するため、引数値どうしの矛盾をすべて検出するものではありません。  
無効にした行は、行番号と原因を診断情報として利用側へ返します。

### 判定の事前計算

適用の時点で、カタログ内の各項目に対して、各行の判定結果を次の 3 つの状態へ事前分類します。

| 状態 | 意味 | 実行時の処理 |
|---|---|---|
| 常に一致 | 引数の値によらず条件式が成立 | 条件判定を省略し、書式展開を実行 |
| 常に不一致 | 引数の値によらず条件式が不成立 | 条件判定を省略し、書式展開を実行 |
| 引数値に依存 | 引数の値によって条件式の成否が決定 | 条件判定と書式展開を実行 |

Table: フィルター事前計算の状態と実行時処理

この分類は、`key`、`id`、`category`、および各引数の有無やデータ型を確定値として扱い、条件式を部分評価 (定数畳み込み) することで算出します。

行ごとの状態は、論理和の規則に従って項目ごとの状態へ集約します。

- いずれかの行が「常に一致」であれば、項目の状態は「常に一致」です。
- すべての行が「常に不一致」であれば、項目の状態は「常に不一致」です。
- それ以外の場合、項目の状態は「引数値に依存」です。項目ごとに、「引数値に依存」となった行の集合をビット集合で保持し、実行時はその行だけを評価します。

事前計算の結果は、フィルター スロットが保持します。  
大きさは、カタログの項目数と行数の上限から決定されるため、フィルター スロットの作成時に確定します。  
正規表現を含まない行の適用では、メモリを動的に確保しません。  
正規表現を含む行は、面ごとの照合器を適用時に作成するため、動的確保の例外です。

メモリは固定長で確保することを原則とします。  
行と項目の組ごとの判定結果と引数の対応表は、引数を参照しない行の分も含めて確保し、使用状況に応じて詰めることはしません。  
行の集合は 64 ビットの語の配列で表し、語の数は行数の上限から決まります。

行数の上限を L、カタログの項目数を E とすると、事前計算の領域は 1 面あたりおおよそ `9 × L × E + (1 + 8 × ⌈L / 64⌉) × E + 164 × L` バイトで、スロットは 2 面を確保します。  
これに、2 面分のフィルター オブジェクト (1 面あたり `64 + L × (16 + 16 × 行幅)` バイト) が加わります。  
事前計算の領域の 2 面分の計算値を次に示します。

| 項目数 | 行数の上限 | 事前計算の領域 (2 面) |
|---|---|---|
| 1,000 | 64 | 1,190,992 バイト (約 1.1 MiB) |
| 1,000 | 256 | 4,757,968 バイト (約 4.5 MiB) |
| 1,000 | 1024 | 19,025,872 バイト (約 18.1 MiB) |
| 10,000 | 64 | 11,720,992 バイト (約 11.2 MiB) |
| 10,000 | 256 | 46,823,968 バイト (約 44.7 MiB) |
| 10,000 | 1024 | 187,235,872 バイト (約 178.6 MiB) |

Table: 行数の上限と項目数ごとの事前計算の領域の計算値

大半は行数と項目数の積に比例するため、行数の上限は必要な分だけ指定します。  
大きなカタログで多くの行を使う場合は、対象の項目を分けた別のカタログで判定することを検討します。

項目ごとの状態は、カタログの項目配列と同じ並びの配列で保持します。  
実行時は、カタログから文字列キーに対応する項目を検索し、その項目の位置で状態を参照します。  
項目の検索は、カタログに有効なインデックス テーブルがあれば `O(1)`、なければ順次探索です。

分類値と文字列キーだけを条件とする行は、すべての項目で「常に一致」または「常に不一致」に分類されます。  
出力詳細度の制御では多くの行がこの形式になるため、実行時の判定の大半は配列参照 1 回で完了します。  
どの状態でも文字列を組み立てるため、可変長引数の抽出は書式展開のために行います。

### 実行形式と評価器

各行の条件式は、後置記法 (逆ポーランド記法) に基づく命令列として、フィルター オブジェクトに格納されています。  
短絡評価は、条件付きジャンプ命令として命令列内に表現します。

命令列の評価は、再帰呼び出しを用いずにスタック マシン方式で実行します。  
評価に必要なスタックの最大深度はコンパイルの段階で確定し、フィルター オブジェクトのヘッダーへ記録します。  
正規表現を含まない行の判定では、メモリを動的に確保しません。  
正規表現による照合は、照合器内部で動的に確保します。

### 差し替え時の再利用

適用の処理では、現在適用されているフィルター オブジェクトと新しいフィルター オブジェクトを、行レコードのハッシュ値によって比較します。  
内容が同一の行については、名前の解決と事前計算の結果を再利用します。

比較は行番号ではなく行の内容で行うため、行の挿入や削除によって行番号が変動した場合も再利用できます。  
事前計算を実行するのは、内容が変更された行だけです。  
ただし、フィルター オブジェクト全体の複製と検証、および項目ごとの集約は毎回行います。  
現在の実装では、新しい各行に対して適用中の行を順に探索するため、行の探索は最悪 `O(L²)`、項目ごとの集約は `O(E × L)` です。  
ここで `L` は格納した行数、`E` はカタログの項目数です。  
正規表現も面ごとにコンパイルし直すため、差し替え全体の処理量は変更行数だけには比例しません。

## デコンパイルと自然文での表現

### デコンパイル

フィルター オブジェクトは、命令列と定数に加えて、引数名と文字列キーの名前を文字列のまま保持します。  
そのため、フィルター オブジェクトから条件式を復元できます。

復元は、後置記法の命令列を中置記法へ戻す処理です。  
括弧は、演算子の優先順位から必要な位置にだけ付与します。  
数値定数は、レコードに記録した記法に従って 10 進数または 16 進数で出力します。  
文字列定数は、二重引用符で囲み、エスケープ シーケンスを復元します。

復元の対象は、フィルター オブジェクトが格納している条件式だけです。  
空行、コメント行、および構文エラーの行は格納していないため、復元できません。

復元した条件式は、空白の位置と余分な括弧が正規化された形式になります。  
復元した条件式を再度コンパイルすると、元のフィルター オブジェクトと同じ命令列になります。  
この性質は、単体テストで確認します。

利用側は、`cplat_string_catalog_filter_get_info` で格納した行数を取得し、`cplat_string_catalog_filter_decompile_line` を行ごとに呼んで復元します。  
条件式リスト全体の復元も、この繰り返しで行います。  
出力先のバイト数が不足する場合は、切り詰めたうえで `CPLAT_ERR_BUFFER_TOO_SMALL` を返します。

デコンパイルはカタログ定義を参照しません。  
コンパイルと同様に、対象のカタログを持たない環境でも実行できます。

### 自然文での表現

カタログ定義を参照できる場合は、条件式を自然文で表現できます。  
カタログの項目が、文字列キーに対応する短い説明 (`brief`) と ID、引数の名前と説明を保持しているためです。

自然文での表現は、フィルター スロットに対して実行します。  
フィルター スロットはカタログ定義と結び付いており、名前の解決も完了しているためです。

| 条件式の要素 | 自然文で使用する情報 |
|---|---|
| 文字列キーの比較 | 対象の項目の `brief` と `id` |
| 引数の比較 | 引数の名前と、引数の説明 |
| 分類値の比較 | 利用側が指定した分類値の名前。指定しない場合は数値 |
| ID の比較 | ID の文字列 |

Table: 条件式の要素と自然文で使用する情報の対応

条件式が文字列キーを 1 つの項目に限定している場合は、その項目の引数の説明を使用します。  
複数の項目が対象となる場合も、引数の名前と説明が共通なら、その説明を使用します。  
項目によって説明が異なる場合は、引数の説明を付けずに表します。

出力する自然文の例は次のとおりです。

```text
条件式:
category <= 3 || (key == SAMPLE_MESSAGES_KEY_FILE_OPEN_FAILED && arg.file_path starts_with "/etc/")

自然文 (日本語):
分類値が 3 以下、または「ファイルのオープン失敗。」(SAMPLE_MESSAGES_ID_0002) かつ
引数 file_path (開けなかったファイルのパス。呼び出し側の指定をそのまま出力します。) が "/etc/" で始まる
```

自然文の文型はライブラリが保持し、ニュートラル言語と日本語を提供します。  
使用する言語は `cplat_string_catalog_get_language()` が返す現在の出力言語です。

ライブラリが保持するのは、判定要素を説明する文型だけです。  
利用側の文字列の内容と文字列キーの体系は、引き続きライブラリで保持しません。  
ただし、[string_catalog モジュール](../../prod/libsrc/cplat/string_catalog/README.md) が定める責務境界のうち、ライブラリが文言を持たないという前提は、この文型の追加によって一部変わります。  
責務境界の記述は、条件式を説明する文型をライブラリが保持する例外を反映済みです。

自然文は、運用者が条件式の内容を確認するための表示です。  
判定処理では使用しません。

## 実行中の差し替えとスレッド安全性

フィルター スロットは、判定処理が参照する内容を 2 面のバッファーで管理します。  
適用の処理は、使用していない面へ結果を構築してから、参照する面を切り替えます。  
面の管理は実装の内部に閉じており、利用側は面を意識しません。

参照する面の切り替えは、読み書きロック (`cplat_local_rwlock`) で保護します。

- 判定処理は、共有モードでロックを取得し、使用中の面を参照します。
- 適用の処理は、使用していない面の構築をロックの外で行い、排他モードでロックを取得して面を切り替えます。
- 切り替え後、以前の面を参照するスレッドは存在しないため、次の適用でその面を再利用できます。

名前の解決と事前計算をロックの外で行うため、適用の処理中もトレースの判定処理は停止しません。  
判定処理が待機するのは、面を切り替える短い区間だけです。

複数のスレッドから同時に適用を要求した場合は、適用専用のロックで直列化します。  
要求順での処理は保証しません。

判定処理ごとに共有モードのロックを取得するため、ロックの取得と解放のコストが判定ごとに発生します。  
このコストがトレースの性能要件を満たさない場合は、ロックを用いない面の切り替え方式を、測定結果に基づいて検討します。

### ソース領域からの取り込み

フィルター オブジェクトを別のスレッドやプロセスから受け取る場合は、ソース領域を使用できます。  
ソース領域は、64 バイトのヘッダーとフィルター オブジェクトを並べた領域で、利用側が先頭アドレスとバイト数で示します。  
共有メモリ、ファイルのマップ、プロセス内の静的領域のどれでも構いません。

ヘッダーには、公開のたびに 2 ずつ増える版番号を置きます。  
0 は未公開、奇数は書き込み中を表します。  
書き込み側は、版番号を奇数にしてから内容を書き、前回の値に 2 を加えた偶数の値を書き込みます。  
書き込み側どうしは排他または呼び出し側で直列化するため、版番号は重複しません。  
版番号は時刻に依存しないため、クロックの分解能や OS の再起動の影響を受けません。  
領域を 0 で埋め直すと版番号は 2 から数え直すため、読み取り側のスロットを結び付け直します。  
結び付けると取り込み済みの版番号は 0 に戻ります。  
前回の値に 2 を加えると 64 ビットを超える場合は、2 へ戻します。  
読み取り側は不一致で変化を判定するため、戻った値でも取り込みます。  
1 秒に 10 億回公開しても上限に届くには約 292 年かかるため、上限に達するのは壊れた値や意図的に大きくした値に限られます。

ファイルをマップした領域は、異なる版のライブラリや異なる行数の上限と行幅で書かれた内容を残している場合があります。  
読み取り側は、ヘッダーの署名、形式版、行数の上限、行幅を版番号の読み直しで一貫性を確かめてから比べ、一致しない公開内容はフィルター オブジェクトを読まずに取り込みの失敗として記録します。  
署名が一致して形式版だけが異なる場合は `CPLAT_ERR_VERSION_MISMATCH`、署名、ヘッダー長、行数の上限、行幅の不一致は `CPLAT_ERR_CORRUPT_DESCRIPTOR` とします。

ヘッダーには、公開時に指定したカタログの識別値も記録します。  
スロットは、作成時に求めた自分のカタログの識別値と一致しない公開内容を、フィルター オブジェクトを読まずに `CPLAT_ERR_IDENTITY_MISMATCH` として記録します。  
条件式中の名前が解決できても、別の版のカタログでは文字列キーの値や引数の位置が異なり得るためです。  
以前の版が書いた領域は識別値が 0 のため取り込まず、新しい版で公開し直すと回復します。

スロットへソース領域を結び付けると、判定付きの組み立てのたびに版番号を 1 回だけアトミックに読みます。  
取り込み済みの値と異なる場合は、適用のロックを待たずに試み、取れた場合だけ取り込みます。

利用側は、結び付けの際に書き込み側の排他 (取得と解放の関数と、その引数) を与えられます。

| 書き込み側の排他 | 取り込みの手順 |
|---|---|
| 与えた場合 | 排他を取り、版番号を読み直して、取り込み済みでなければ複製します。複製を終えた時点で排他を解放し、検証と適用は排他の外で行います (二重確認)。複製の間に書き込みが重ならないため、書き込み中の領域を読みません |
| 与えない場合 | ロックを取らずに複製し、複製の後に版番号を読み直します。値が変わっていれば複製を捨てて次の判定で改めて取り込みます (seqlock と同じ形)。書き込み中の領域を読み得ますが、一貫しない内容は版番号とハッシュ値で捨てます |

Table: 書き込み側の排他の有無と取り込みの手順

どちらの場合も、版番号の確認はロックを取らない 1 回のアトミックな読み取りで、変化がなければ排他を取りません。  
排他の下で奇数の版番号が見えるのは、書き込みの途中で書き込み側が停止した場合だけであり、次の公開まで取り込みません。  
領域の確保と共有、および排他の実装は利用側の責務です。  
cplat は、先頭アドレスとバイト数、および排他を取得、解放する関数の組 (`cplat_string_catalog_filter_source_lock`) を受け取るだけで、領域や排他の方式を知りません。  
公開 (`cplat_string_catalog_filter_source_publish`) は、関数の組を受け取った場合に書き込みの間だけ排他を取ります。  
受け取らない場合は、呼び出し側が公開を直列化します。

排他の実装には、次の条件を求めます。

- 同じプロセスのスレッドの間と、領域を共有するプロセスの間の両方で排他になること。
- 排他を保持したプロセスが異常終了した場合も、ほかのプロセスが取得できるようになること。
- cplat は排他を再入して取得しないため、再入に対応する必要はないこと。

設計の経緯は、string-catalog-sample の `string-catalog-filter-migration-design.md` の「条件の取り込みを版番号の比較で検知する」に記録しています。

`cplat_string_catalog_filter_compile` は、条件式リストの配列の先頭アドレス、入力行数、行幅、格納する行数の上限と、出力先の領域とそのバイト数を受け取ります。  
出力先のバイト数が `CPLAT_STRING_CATALOG_FILTER_IMAGE_SIZE` の算出結果に満たない場合は、エラーを返します。  
構文エラーの行は診断情報へ記録し、フィルター オブジェクトには格納せず、他の行のコンパイルを続行します。  
無効にした行の診断情報は、利用側が用意した診断情報の配列へ、配列の容量までを格納し、無効にした行の総数を出力引数へ格納します。

`cplat_string_catalog_filter_slot_create` は、カタログ、文字列キーの名前解決テーブルと要素数、分類値の名前、行数の上限、および行幅を受け取ります。  
事前計算の結果を格納する 2 面のバッファーは、この時点で確保します。  
適用できるフィルター オブジェクトは、作成時に指定した行数の上限と行幅に一致するものだけです。

`cplat_string_catalog_filter_slot_apply` は、フィルター オブジェクトの領域とそのバイト数を受け取ります。  
内容はフィルター スロットの内部へ複製するため、呼び出しの完了後、利用側はその領域を再利用または解放できます。  
名前を解決できない行、および事前計算ですべての項目が「常に不一致」となる行は無効として扱い、診断情報を返します。  
一部の項目で型が合わない場合は、その項目の比較要素を偽として扱います。  
フィルター オブジェクトの検証に失敗した場合はエラーを返し、現在の内容を維持します。

`cplat_string_catalog_filter_decompile_line` は、カタログ定義を参照しません。  
`cplat_string_catalog_filter_slot_describe_line` は、フィルター スロットが保持するカタログ定義の `brief`、`id`、および引数の説明を使用します。  
どちらも、出力先のバイト数が不足する場合は、切り詰めたうえで `CPLAT_ERR_BUFFER_TOO_SMALL` を返します。

`cplat_string_catalog_filter_slot_test` は、可変長引数を渡すことなく判定が確定できるかを利用側が事前に確認するための関数です。  
たとえば、判定結果が「常に一致」である文字列を、利用側は引数値を計算する前に強制出力の対象と判断できます。

`cplat_string_catalog_filter_slot_vformat` は、条件一致の有無にかかわらず文字列を組み立て、一致の有無を出力引数へ格納します。  
戻り値は書式展開の結果であり、条件に一致しなかったことをエラーとして扱いません。  
一致した文字列をどう扱うかは利用側が決めます。  
トレースと組み合わせる場合は、一致した文字列のトレース レベルを `CPLAT_TRACE_LEVEL_TO_FORCE` で強制出力へ引き上げ、一致しない文字列は元のレベルのまま出力先へ渡します。

フィルター スロットは、作成時に指定したカタログ オブジェクトの参照を内部で保持し続けます。  
そのため、フィルター スロットを使用する間は、対象のカタログ オブジェクトが有効であり続ける必要があります。

`filter_slot_format` および `filter_slot_vformat` は、カタログ オブジェクトを明示的な引数として受け取らず、フィルター スロットが保持するカタログ定義を使用します。  
フィルター スロットと異なるカタログ オブジェクトを誤って組み合わせて呼び出す不整合を、API の構造によって防止するためです。

利用側における条件式リストの読み込みと、トレース出力処理の実装例は次のとおりです。

```c
/* 条件式リストの差し替え (ファイルの変更を検出した時点で実行) */
char lines[64][256];
static unsigned char image[CPLAT_STRING_CATALOG_FILTER_IMAGE_SIZE(64, 256)];
cplat_string_catalog_filter_diagnostic diagnostics[8];
size_t line_count = load_filter_file(filter_file_path, lines, 64); /* 利用側の関数 */
size_t invalid_count = 0;

if (cplat_string_catalog_filter_compile(&lines[0][0], line_count, sizeof(lines[0]), 64, image, sizeof(image), diagnostics,
                                        8, &invalid_count) == CPLAT_OK)
{
    cplat_string_catalog_filter_slot_apply(slot, image, sizeof(image), diagnostics, 8, &invalid_count);
}

/* トレースの出力 */
int matched = 0;
char text[CPLAT_STRING_CATALOG_TEXT_MAX];

if (cplat_string_catalog_filter_slot_format(slot, text, sizeof(text), &matched, SAMPLE_MESSAGES_KEY_FILE_OPEN_FAILED,
                                            path, error_code) == CPLAT_OK)
{
    /* 条件式に一致したトレースは、出力先のしきい値によらず出力する */
    if (matched != 0)
    {
        level = CPLAT_TRACE_LEVEL_TO_FORCE(level);
    }
    cplat_tracer_write(tracer, level, NULL, text);
}
```

[文字列カタログの機能仕様](../functional-spec/string_catalog.md) は、条件式フィルターの機能要件、品質要件、および制約を反映済みです。  
条件式の変換と復元、カタログへの関連付け、判定と書式展開、実行中の差し替え、自然文の説明、およびソース領域による受け渡しを定めています。

## 段階的実装計画

次の 3 段階の主要機能は実装済みです。  
ソース領域による受け渡しと実プロセス間の配布の進捗は、[移行設計](../../../string-catalog-sample/prod/src/cmd/string-catalog-filter-sample/string-catalog-filter-migration-design.md) に記録しています。

### 第 1 段階: コンパイルと判定 (実装済み)

- 条件式の構文解析器、およびフィルター オブジェクトの生成の実装
- フィルター オブジェクトの形式の定義、大きさの算出マクロ、および検証処理の実装
- 適用時の名前解決、事前計算と行の集約、および後置命令列のスタック評価器の実装
- 2 面のバッファーと読み書きロックによる、実行中の差し替えの実装
- 変更していない行の事前計算の結果を再利用する処理の実装
- 公開 API (`filter_compile`、`filter_validate`、`filter_slot_create`、`filter_slot_dispose`、`filter_slot_apply`、`filter_slot_test`、`filter_slot_format`、`filter_slot_vformat`) の実装
- 単体テストの作成、および機能仕様書の改訂

### 第 2 段階: 名前解決と行単位の編集 (実装済み)

- カタログ定義生成器 (`string_catalog_gen.py`) による文字列キー名前解決テーブルの自動出力
- 行単位の編集 (`filter_compile_line`、`filter_insert_line`、`filter_remove_line`) の追加
- デコンパイル (`filter_decompile_line`) と、復元した条件式の再コンパイルによる一致の確認。全体の復元は行ごとの復元を繰り返せば足りるため、`filter_decompile` は設けません
- 正規表現による一致判定 `matches` の追加 (内部実装として `cplat_regex` を使用)。第 3 段階の配布より先に導入しました
- 事前計算ですべての項目が「常に不一致」となる行に対する診断通知の実装。事前計算がすべての項目で「常に不一致」となる行を、`CPLAT_STRING_CATALOG_FILTER_LINE_ERROR_NEVER_SATISFIABLE` で無効にします

### 第 3 段階: 自然文での表現と利用例の整備 (実装済み)

- 自然文の文型 (ニュートラル言語と日本語) と `filter_slot_describe_line` の実装
- `string_catalog` モジュールの責務境界の記述の更新
- `string-catalog-sample` における、外部ファイルの条件式リストを用いたトレースの出力詳細度の変更例と、条件の一覧表示の追加。`string-catalog-filter-sample` の `load` と `save` で実装しました

## 決定済みの事項

- **同名引数で型が異なる場合の扱い** (決定済み):  
  型が一致しない項目に対する比較演算は、`!=` を含めて偽として評価し、否定と論理結合はその値に対して行います。  
  その結果、どの項目に対しても成立し得ない行は、適用の時点で `CPLAT_STRING_CATALOG_FILTER_LINE_ERROR_NEVER_SATISFIABLE` として通知します。
- **名前解決テーブルの公開インターフェイス形式** (決定済み):  
  トレース種別の生成物ごとの関数 `<module>_key_names()` として提供します。  
  公開範囲 `api` では公開せず、利用側は名前解決テーブルを指定せずにスロットを作る `<module>_create_filter()` を使います。
- **行幅から導く領域長の算出式** (決定済み):  
  行レコードは、16 バイトの見出しと、行幅 1 バイトあたり 8 バイトの命令領域と 8 バイトの定数領域で構成し、`16 + 16 × 行幅` バイトとします。  
  命令は 1 個 8 バイトで行幅と同じ個数まで、定数領域は行幅の 8 倍のバイト数です。  
  計算は公開ヘッダーのマクロ `CPLAT_STRING_CATALOG_FILTER_RECORD_SIZE` と `CPLAT_STRING_CATALOG_FILTER_IMAGE_SIZE` にあります。
- **各種制限値** (決定済み):  
  次の値で決定し、公開ヘッダーの定数として定義済みです。

  | 制限 | 値 | 定数 |
  |---|---|---|
  | 行数の上限 | 1024 | `CPLAT_STRING_CATALOG_FILTER_LINE_MAX` |
  | 行幅 | 8 以上 1024 以下 | `CPLAT_STRING_CATALOG_FILTER_LINE_WIDTH_MIN`、`_MAX` |
  | 1 行の判定要素 | 32 個以下 | `CPLAT_STRING_CATALOG_FILTER_PREDICATE_MAX` |
  | 括弧と否定の入れ子 | 16 段以下 | `CPLAT_STRING_CATALOG_FILTER_NESTING_MAX` |
  | 1 行が名前で参照する引数 | 8 種類以下 | `CPLAT_STRING_CATALOG_FILTER_ARGUMENT_REFERENCE_MAX` |
  | 1 行の文字列キーの名前 | 16 個以下 | `CPLAT_STRING_CATALOG_FILTER_IDENTIFIER_REFERENCE_MAX` |
  | 1 行の正規表現のパターン | 4 個以下 | `CPLAT_STRING_CATALOG_FILTER_PATTERN_REFERENCE_MAX` |
  | 正規表現で照合する文字列 | 512 バイト以下 | `CPLAT_STRING_CATALOG_FILTER_PATTERN_SUBJECT_MAX` |

  Table: 条件式フィルターの制限値

- **フィルター オブジェクトとカタログ定義の対応の検証** (決定済み):  
  コンパイルはカタログ定義に依存しない方針を保つため、識別値はフィルター オブジェクトではなく、ソース領域のヘッダーへ記録します。  
  公開する側が `cplat_string_catalog_filter_get_catalog_id` で求めた識別値を指定し、取り込む側のスロットは自分のカタログの識別値と一致しない公開内容を取り込みません (「ソース領域からの取り込み」を参照)。  
  識別値は、判定に関わる定義 (文字列キー、分類値、ID、引数の種別と名前) から求めます。  
  スロットへ直接適用するフィルター オブジェクトは、呼び出し側がカタログとの対応に責任を持ちます。
- **自然文の文型の粒度** (決定済み):  
  演算子ごとに、主語と値の間に置く語と、値の後ろに置く語の組を持ちます。  
  大文字と小文字を区別しない演算子は、区別する演算子と同じ文型に注記を加えて表します。
- **自然文における語順の扱い** (決定済み):  
  文字列カタログの書式展開は再利用せず、主語、値の前の語、値、値の後ろの語の順に並べる表で持ちます。  
  日本語とニュートラル言語の語順の違いは、値の前後の語で吸収します。
- **複数のカタログへの適用** (決定済み):  
  複数のカタログをまたぐ条件式はサポートしません。  
  1 つのフィルター スロットは 1 つのカタログに結び付き、複数のカタログで判定する場合はカタログごとにスロットを作成します。

## 型が合わない比較要素を条件式の作成時に通知する

「型が合わない比較要素を偽とする」という判定仕様は維持し、そのような比較要素があることを、条件式を作成する人へ知らせる手段を追加します。  
同名の引数が項目によって文字列と数値に分かれる場合も、`!=` と `!(==)` の結果が分かれるなど意図と判定がずれやすいため、通知の対象にします。

### 通知の検出はスロットで行う

型の不一致は、条件式とカタログの両方を知る層でなければ検出できません。

| 層 | 知っていること | 型の不一致の検出 |
|---|---|---|
| コンパイル | 条件式だけ | できない。引数の型を知らない |
| カタログと生成器 | 引数の名前と型だけ | できない。同名の引数の型が分かれていることは分かるが、条件式で比較しない限り問題にならない |
| フィルター スロット | カタログ、名前解決テーブル、分類値の名前。適用時に、行と項目の組ごとに名前を解決している | できる |
| 配布で取り込む側 | フィルター スロット | できるが、条件式を書いた人へ届ける経路がない |

Table: 型の不一致を検出できる層

条件式とカタログの結び付けはフィルター スロットの責務であるため、検出もスロットで行います。  
cplat は警告を返すだけとし、人へ見せるのは条件式を編集し、公開する利用側のアプリです。

当初は、カタログ、名前解決テーブル、分類値の名前を個別に受け取る独立した関数 `cplat_string_catalog_filter_check_catalog` を検討しました。  
この方式は、名前解決テーブルの検証と名前の解決をスロットと二重に持つことになるため、スロットを受け取る方式に改めました。  
管理ツールは、確認のためにスロットを作成する必要があります。

### 確認関数は適用を試行し、面を切り替えない

`cplat_string_catalog_filter_slot_check` は、フィルター オブジェクトを適用と同じ手順で検証し、名前を解決して事前計算します。  
適用との違いは、判定が参照する面を切り替えないことと、警告を返すことだけです。  
無効にする行の診断情報は、適用と同じ内容を返します。

構築には、判定が参照していない面を使い、適用と同じロックで直列化します。  
判定が参照する面とその内容は変わらないため、判定用のロックは取りません。  
ソース領域からの取り込みは、確認と重なった場合は待たずに次の判定で取り込みます。

警告は無効にする行の診断とは分け、警告だけなら関数は `CPLAT_OK` を返します。  
警告の件数は、呼び出し側の配列容量にかかわらず総数を返し、詳細は容量まで記録します。  
名前を解決できない行と、正規表現をコンパイルできない行は、項目と結び付かないため警告の対象にしません。  
成立し得ない条件として無効にする行は、型の不一致がその原因であり得るため、警告の対象にします。

### 警告は 2 種類とする

| 警告種別 | 検出する条件 | 単位 |
|---|---|---|
| 型の不一致 (`TYPE_MISMATCH`) | 比較要素の定数が、項目の引数の型区分と比較できない | 行、比較要素、項目の組 |
| 型区分の混在 (`MIXED_ARGUMENT_TYPES`) | 名前で参照した引数が、カタログ内で文字列の項目と文字列以外の項目の両方に現れる | 行と引数名の組 |

Table: 型の不一致の警告種別

型の不一致の有無は、引数種別の名称の違いではなく、現行の比較規則で判断します。  
たとえば、同名の INT32 と UINT64 は数値として比較できるため、警告しません。  
`has` は引数の有無だけを調べるため、どちらの警告の対象にもしません。  
項目に引数が無い場合は、型の不一致の警告の対象にしません。項目に無い引数を参照する行は、意図して複数の項目にまたがって書くことが多いためです。

型区分の混在は、比較できる項目が一部にあっても警告します。  
同じ名前ならすべての項目が判定の対象になると期待されやすいためです。  
区分は、文字列と文字列以外の 2 つに分けます。  
ポインターは null 以外との比較で符号なしの整数として扱うため、文字列以外に含めます。  
ポインターと整数の混在は、`== null` のような比較で型の不一致の警告として現れます。  
混在はカタログ全体で判断し、文字列キーや分類値の条件によって行の対象外となる項目も含めます。  
インデックスで指定した引数 (`arg[<n>]`) は名前を持たないため、型区分の混在の対象にしません。

1 件の警告は、次の情報を持ちます。

| 情報 | 型の不一致 | 型区分の混在 |
|---|---|---|
| 行の位置 | フィルター オブジェクト内の 0 起点の行 | 同左 |
| 比較要素の位置 | 行内の比較要素を条件式に現れる順に数えた 0 起点の番号 | 引数名が最初に現れる比較要素 |
| 文字列キーと引数の位置 | 型が合わない項目と、その項目での引数の位置 | 文字列の引数を持つ項目の 1 つと、その引数の位置 |
| もう一方の文字列キーと引数の位置 | 使用しない (引数の位置は -1) | 文字列以外の引数を持つ項目の 1 つと、その引数の位置 |

Table: 型の不一致の警告が持つ情報

引数名は、カタログの項目と引数の位置から利用側が取得します。

### 説明文に型区分の混在を注記する

条件の説明 (`cplat_string_catalog_filter_slot_describe_line`) は、型区分の混在がある引数名を、説明文の末尾に注記します。  
確認関数を呼ばない利用側でも、条件の一覧表示で気付けるようにするためです。

| 文型 | 注記 |
|---|---|
| 日本語 | ` (注意: 引数 job_name はカタログ内に文字列型と数値型が混在しているため、意図した判定結果にならない可能性があります)` |
| ニュートラル言語 | ` (Note: argument job_name has both string and numeric types in the catalog; the result may not be as intended.)` |

Table: 型区分の混在の注記

混在する引数名が複数ある場合は、引数名ごとに注記します。ニュートラル言語の文型を、引数の数によって変えずに済むためです。  
同じ引数名を複数の比較要素で参照しても、注記は 1 回だけです。  
判定の対象を決める規則は、確認関数の型区分の混在と同じです。  
注記は条件式の言い換えではないため、説明文に収まらない場合は他の部分と同じく切り詰めます。

## 性能測定と差し替え全体の処理量は残課題

判定ごとの共有ロックの取得と解放、引数値に依存する条件、正規表現の照合、および適用時の待機時間を測定する必要があります。  
行数、項目数、および変更行数を変えて、許容する所要時間と比較します。  
メモリ量の計算値と、書式展開単体の測定結果は、フィルター全体の性能測定の代わりにはなりません。

差し替え全体の処理量を変更行数に比例させる目標については、行の探索、集約、全体の複製と検証、および正規表現の再コンパイルを含めて検討します。  
共有ロックの取得と解放がトレースの頻度に対して許容できない場合の代替方式 (参照カウントや世代管理による入れ替え) は、測定結果に基づいて判断します。
