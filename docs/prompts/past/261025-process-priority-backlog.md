## BL-001 プロセス優先度のプラットフォーム共通抽象化

### 概要と問題点

- **現状の事象**: 今回の案件では、Linux と Windows それぞれに特化した優先度設定 API だけを設けます。両方のプラットフォームで動く利用側は、`PLATFORM_*` で分岐して別々の API を呼ぶ必要があります。
- **本来あるべき姿**: 「バックグラウンド処理として優先度を下げる」「応答性のため優先度を上げる」など、利用側の意図を表す共通 API があり、各プラットフォームの特化 API へ写像されます。

### 経緯と見送り理由

- **摘出契機**: 依頼時にユーザーが「抽象化は今後の課題とする」と明示しました。
- **今回の見送り理由**: スコープ外 (ユーザー指示)。

### 影響範囲とリスク

- **影響対象**: `cplat/runtime/process_priority_linux.h` と `cplat/runtime/process_priority_windows.h` の API と、その利用側。
- **放置した場合のリスク**: 利用側ごとにプラットフォーム分岐と値の対応付けが重複します。

### 推奨される対応策

- **恒久対応案**: 特化 API の利用実績から共通の意図 (「バックグラウンド処理として下げる」「応答性のため上げる」など) を抽出し、[プラットフォーム抽象化ガイドライン](../../platform-abstraction-guideline.md) に沿って `cplat/runtime/process_priority.h` に `cplat_process_priority_*` の共通 API を設計します。共通 API は各 OS の特化 API へ写像し、特化 API は残します。
- **参考情報**: `prompt/current/process-priority-discussion.md`
