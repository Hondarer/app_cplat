# sym_loader で 1 つのコールバック元に複数のコールバック先を持たせる検討

ファイル名: `261108-sym-loader-multi-target-discussion.md`

`sym_loader` を、1 つのコールバック元に複数の移譲先を設定し、解決できた移譲先を設定順に取得できる形へ拡張します。  
利用側が移譲先のリストを受け取り、すべてを呼ぶか先頭だけを呼ぶかを自分で決める、という形は版 1 で決まりました。  
公開関数は件数と添字、先頭は設定に書いた順、先から元へ戻る動作は保証しない、通常の `cplat_sym_loader_info` は利用側のリストだけ、と版 2 で決まりました。  
診断用の無効な設定項目は、エントリごとの件数と添字で得る、と版 3 で決まりました。  
`CPLAT_SYM_LOADER_ENTRY_INIT` の未使用の型引数は削り、関数型は取得側だけが持つ、と版 4 の差し戻しで決まりました。  
版 6 の照合で、最終仕様に未確定の契約と、検討がまだ決めていない具体化が見つかりました。  
版 7 では、それらを [Q-018](#q-018-公開構造体のレイアウト) から [Q-028](#q-028-init-および-dispose-と関数呼び出しの並行) で確認します。  
版 8 では、保存された回答を記録します。診断理由の値と、重複キーを診断へ返す範囲は [Q-029](#q-029-片方だけが-default-の診断理由) と [Q-030](#q-030-重複キーを診断で返す範囲) で確認します。  
版 9 では、保存された回答を記録しました。追加の質問はないため、最終仕様を更新します。

この文書では、コールバック元を設定のキー (`func_key`) と、それに対応する `cplat_sym_loader_entry` 1 個とします。  
コールバック先を、そのキーに対するライブラリ名と関数名の組とします。  
`override-sample` の `base_calc` では、元が `base_calc`、先が設定された `lib` と `func`、組み込み実装が `result = a + b` です。

版 1 の回答 (2026-11-08 08:19:00 JST、Tetsuo Honda、検討用 Markdown の保存時刻) で確定した内容は次のとおりです。

- `cplat` は移譲先をリストで返します。すべてを呼ぶか、先頭の 1 つだけを呼ぶかは、利用側のコードが決めます。リストの長さが 0 のときは移譲先がありません ([Q-001](#q-001-複数の先と組み込み実装の関係)、[Q-002](#q-002-複数の先を呼ぶ主体))。
- 使えない先はリストから外し、使えた先を残します。名前が空、名前が長すぎる、ライブラリを開けない、シンボルが見つからない、の 4 つが使えない先です ([Q-003](#q-003-使えない先が混ざったときの適用))。
- 戻り値の集約は `cplat` が持ちません。`base_calc` は、定義が無いときは組み込み実装、定義があるときは最初の定義だけを使います。イベント通知のようにすべての先を呼ぶ利用側は、今回のサンプルには含めません ([Q-004](#q-004-元の関数が返す結果))。
- `lib` と `func` がどちらも `default` である指定は、先が 1 件のときだけ明示的既定値です。並びに `default` があるキーは適用しません。この場合は、使えない先を 1 件外す処理にはせず、キー全体を未適用にします ([Q-005](#q-005-明示的な既定値の混在))。
- 設定の値がオブジェクトなら先は 1 件、配列なら各要素が先です ([Q-006](#q-006-設定ファイルの書き方))。
- 1 つの `cplat_sym_loader_entry` がそのキーの先の列を持ちます ([Q-007](#q-007-先を保持する単位))。
- 1 つのキーの件数に、ファイル全体の `1024 * 1024` バイト以外の上限は設けません ([Q-009](#q-009-1-つのキーに書ける件数))。
- `override-sample` の `base_calc` を今回の変更に含めます。計算のサンプル設定には複数の移譲先を書かず、0 件と 1 件の観測できる結果は変えません ([Q-011](#q-011-override-sample-を変更に含めるか))。
- 検証は `sym_loader` の単体テスト 5 本、必要な `exportTest`、`override-sample` の単体テストです ([Q-012](#q-012-検証の範囲))。

- 移譲先は `cplat_sym_loader_count` と `cplat_sym_loader_get`、型付きの `cplat_sym_loader_get_as` で渡します。`cplat_sym_loader_resolve` と `cplat_sym_loader_resolve_as` は削除します。件数 0 は移譲先なし、範囲外の添字は NULL、先頭は添字 0 です ([Q-013](#q-013-移譲先リストの公開関数)、[Q-008](#q-008-既存の-resolve-の戻り値))。
- 件数と取得は、削除する `cplat_sym_loader_resolve` と同じくスレッド セーフです。`cplat_sym_loader_init` と `cplat_sym_loader_dispose` は、今どおり単一スレッドで呼びます。これは [Q-013](#q-013-移譲先リストの公開関数) が `resolve` の役割を置き換えたことに伴う、現行契約の引き継ぎです。
- `lib` と `func` がどちらも `default` で先が 1 件のときは、リストの長さは 0、`cplat_sym_loader_is_default` は 1 です。並びに `default` があるキーと、未設定のキーは、どちらも長さ 0 かつ `cplat_sym_loader_is_default` は 0 です。長さ 0 のときの `base_calc` は、明示的既定値、並びに `default` があるキー、未設定のいずれでも、組み込みの加算です ([Q-004](#q-004-元の関数が返す結果)、[Q-005](#q-005-明示的な既定値の混在)、[Q-011](#q-011-override-sample-を変更に含めるか)、[Q-013](#q-013-移譲先リストの公開関数))。

### 機能改善と公開インターフェイスの対応

解決できた移譲先を設定順に取得する機能は `count` / `get`、除外した項目を調査する機能は `reject_count` / `reject_get` が担当します。呼び出す範囲と戻り値の集約は利用側に残します。これにより、先頭だけを使う計算処理と、全件を呼ぶイベント通知を同じ取得方式で扱えます。今回追加するサンプルは計算処理だけです。

公開関数は新規の 5 件だけではありません。既存の `init`、`dispose`、`is_default`、`info` と合わせ、`sym_loader` の公開関数は 9 件です。追加は `count`、`get`、`reject_count`、`reject_get`、`is_failed` です。すべて `cplat_sym_loader_` 接頭辞を持ち、公開宣言、エクスポート表、`mock_cplat` の関数型を一致させます。

`resolve` の削除と公開構造体の変更はバイナリ ABI に影響します。`resolve_as` の削除、`get_as` の追加、初期化マクロの引数削減はソース API の変更です。マクロ自体はエクスポート シンボルを持ちません。構造体はヘッダー上の完全な型のままです。先の列は非公開の管理構造体に置き、公開メンバーの具体形は最終仕様に書きます。

## 調査で確認した事実

`cplat_sym_loader_entry` は、ライブラリ名、関数名、モジュール ハンドル、関数ポインターを 1 つずつ持ちます。  
設定の値はオブジェクト 1 つで、`lib` と `func` という 2 つの文字列です。  
`cplat_sym_loader_init` は、キーが一致した最初のエントリへその組を書き、内側の走査を抜けます。  
`cplat_sym_loader_resolve` は `void *` を 1 つ返します。  
`CPLAT_SYM_LOADER_ENTRY_INIT` の型引数は、マクロの展開に使われていません。関数型は、利用側が `cplat_sym_loader_resolve_as` で付けます。

`base_calc` は、返ったポインターが NULL でなければその関数を 1 回呼び、NULL ならば `result = a + b` を実行します。  
ポインターが NULL になる理由は、未設定、明示的な既定値、解決失敗、シンボル未検出のどれでも同じです。  
区別できるのは、エントリの `resolved` と `cplat_sym_loader_is_default` です。

| 値 | 条件 | 関数ポインター |
| --- | --- | --- |
| 1 | シンボルを取得した。ライブラリは開けたがシンボルが無い場合も含む | 取得時はアドレス。シンボルが無いときは NULL。ハンドルは閉じる |
| 2 | `lib` と `func` がどちらも `default` | NULL |
| -1 | ライブラリ名または関数名が空 | NULL |
| -2 | 拡張子を足したライブラリ名が `CPLAT_SYM_LOADER_NAME_MAX` に収まらない | NULL |
| -3 | ライブラリを開けない | NULL |

Table: 現在の `resolved` の値

`cplat_sym_loader_info` は、`resolved` が負のエントリがあるとき `CPLAT_ERR_UNKNOWN` を返します。  
シンボルが無くても `resolved` は 1 なので、この関数は失敗にしません。  
`cplat_sym_loader_is_default` は、`resolved` が 2 のときだけ 1 を返します。

機能仕様の「実行時の機能差し替え」は、対象の機能、読み込むモジュール、解決するシンボルを、それぞれ単数で書いています。  
解決に失敗した差し替えは適用せず、そのために通常の起動は止めません。  
差し替えた機能から、同じ差し替え対象を再び呼ぶ動作は保証しません。  
機能仕様には、関数名、型、設定ファイルの書式を書きません。振る舞いが変わった場合は、同じ変更でこの節を見直します。

初期化と解放は、単一スレッドの段階で呼ぶ契約です。解決はスレッド セーフです。  
設定ファイルの上限は `CONFIG_FILE_MAX` (`1024 * 1024` バイト) です。  
初期化は、ライブラリ名と関数名を `strlen` によるバイト数で判定し、終端を除いて 255 バイトまで取り込みます。解決時は、ライブラリ名に拡張子を加えた長さが 256 バイト未満であることも求めます。このため、現行のライブラリ名の上限は Linux で 252 バイト、Windows で 251 バイトです。関数名の上限は 255 バイトです。  
公開構造体の大きさを変えると、このヘッダーを翻訳している利用側の再ビルドが必要です。  
リポジトリ内で `cplat_sym_loader_resolve_as` を呼んでいるのは `base_calc` だけです。

### Q-001 複数の先と組み込み実装の関係

**Status**

解決済み

**Question**

複数のコールバック先を定義したとき、元の機能の実行はどうなりますか。

**Context**

今の `sym_loader` は差し替えです。先が 1 つ解決できれば、利用側はその関数を 1 回呼び、組み込み実装は呼びません。  
依頼の「複数のコールバック先」は、先をすべて実行する意味にも、候補から 1 つを選ぶ意味にも読めます。  
この選択で、機能仕様の「解決に成功した場合は、利用側がその参照先を使用できます」の参照先が 1 つなのか複数なのかが決まります。

`base_calc(1, 2, &result)` を例にします。組み込み実装は `result = 1 + 2` です。設定は次の 2 件です。

```jsonc
"base_calc": [
  { "lib": "liboverride", "func": "override_calc" },
  { "lib": "libaudit", "func": "audit_calc" }
]
```
