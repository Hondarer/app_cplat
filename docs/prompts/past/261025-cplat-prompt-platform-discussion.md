## 調査で確認した実装上の差

通常プロンプトは `prompt_linux.c` と `prompt_windows.c` に端末処理を持ち、固定プロンプトは `pinned_prompt.c` 内に同様の処理を持っています。  
raw モードへの移行・復帰、入力読み取りと Windows の UTF-16 入力処理が重複しています。  
Linux の SIGWINCH ハンドラーと通知状態も両者に分かれています。

Linux の通常プロンプトは取得した幅が正なら採用しますが、固定プロンプトは幅と高さが両方正でなければ 80 列・24 行を使います。  
Windows のブロッキング入力は 100 ms の待機タイムアウトで `-2` を返し、短時間の入力待ちは 50 ms です。  
これらを単純に一つの処理へ置き換えると、端末サイズ取得に失敗した場合などの動作が変わる可能性があります。
