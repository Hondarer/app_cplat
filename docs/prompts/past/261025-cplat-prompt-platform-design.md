# プロンプトの端末処理共通化 最終仕様

検討 ID: CPLAT-PROMPT-PLATFORM

仕様版: 1

前提合意版: 4

状態: 承認済み (対話の「承認」により仕様版 1 を確定)

## 通常プロンプトと固定プロンプトで端末処理を共有する

通常プロンプトと固定プロンプトが個別に保持する端末判定、端末サイズ取得、raw モード制御、リサイズ検知、ブロッキング入力と短時間待機入力を共通化します。  
両プロンプトは同一プロセスで同時に有効にならない前提です。  
同時入力の調停は追加せず、通常と固定を順に利用した際の端末設定とシグナル ハンドラーの復元を検証します。

公開関数、公開型、公開シグネチャは追加・変更しません。  
入力編集、履歴、補完候補の選択、横スクロール、固定領域の配置と描画は、それぞれの既存処理を継続して使います。  
非 TTY の行入力処理は既存処理を使います。

## 共通処理は prompt モジュールの私有実装に置く

以下のパスは、特記しない限り `app/cplat/` からの相対パスです。

Table: 端末処理の共通化におけるファイルの責務

| 対象 | 責務と変更 |
| --- | --- |
| `prod/libsrc/cplat/prompt/prompt_platform.h` | 共通状態、内部入力結果、共通関数と OS 別関数の宣言を置く新規の私有ヘッダー |
| `prod/libsrc/cplat/prompt/prompt_platform.c` | 端末判定と共通の状態管理を実装する |
| `prod/libsrc/cplat/prompt/prompt_linux.c` | Linux のサイズ取得、termios、SIGWINCH、read/select を両プロンプト向けに実装する |
| `prod/libsrc/cplat/prompt/prompt_windows.c` | Windows のサイズ取得、コンソール モード、待機、UTF-16 入力を両プロンプト向けに実装する |
| `prod/libsrc/cplat/prompt/prompt_state.h` | 通常プロンプトの私有状態を定義する |
| `prod/libsrc/cplat/prompt/prompt.c` | 共通状態を使い、入力結果と復元結果を公開戻り値へ変換する |
| `prod/libsrc/cplat/prompt/pinned_prompt.c` | ファイル内の重複した OS 依存処理を除去し、共通処理を呼ぶ |

共通状態の型は `prompt_platform_context`、関数は `prompt_platform_` 接頭辞とします。  
主要操作は端末判定、サイズ取得、raw モードへの移行と復元、待機入力、短時間待機入力です。  
OS 非依存の入口と OS 別の下位関数を分ける場合は、下位関数を `prompt_platform_os_` 接頭辞とします。  
新しい関数は公開 API とせず、私有ヘッダーの宣言に契約を記載します。

既存の `prod/include_internal/cplat/prompt/prompt_internal.h` の通常プロンプト状態は `prompt_state.h` へ移します。  
旧プラットフォーム関数の宣言は共通インターフェイスに置き換え、旧ヘッダーと `prod/include_internal/cplat_internal.h` 内の包括インクルードを除去します。  
依存するテストは、必要な私有ヘッダーを明示的に参照する構成へ変更します。  
入力編集など、他モジュールとの共有が必要な既存の内部インターフェイスは配置を維持します。

新規ソースは既存の prompt ディレクトリ内に配置し、既存の走査でビルドします。  
製品側の `ADD_SRCS` への相対パス列挙や、生成 makefile の手動変更は行いません。

## 各ハンドルが端末の保存状態を所有する

両ハンドルに `prompt_platform_context` を埋め込みます。  
コンテキストは元の端末設定、入力ハンドル、端末設定の復元義務、Windows の UTF-16 入力バッファーを保持します。  
初期化時は未取得状態とし、新たな動的確保は必要としません。

Linux の SIGWINCH ハンドラー、保留通知、以前のハンドラーと登録状態は、OS 別実装内の static 変数に集約します。  
登録したコンテキストにはハンドラーを復元する義務を記録します。  
シグナル ハンドラーは保留フラグの設定だけを行い、ハンドルや動的メモリを参照しません。  
前のハンドラーと端末設定は、復元義務が残っている間は上書きしません。  
新しい入力を始める前に前回の復元未完項目があれば復元を試み、失敗したら新しい入力を開始せず `CPLAT_ERR_UNKNOWN` を返します。

取得と解放の境界では、成功した状態遷移に合わせて保留通知をクリアし、前回の通知を次のプロンプトへ持ち越しません。  
登録・復元の成否を確認し、成功した項目だけ復元義務を解除します。  
複数の復元項目がある場合は、一方の失敗だけを理由に他方の復元を省略しません。

## 端末サイズは寸法ごとに検証する

サイズ取得に成功した場合は、幅と高さを独立に検証します。  
正の幅はそのまま採用し、0 以下の幅は 80 列とします。  
正の高さはそのまま採用し、0 以下の高さは 24 行とします。  
OS のサイズ取得自体が失敗した場合は 80 列・24 行とします。

通常プロンプトは取得した幅を描画に使い、固定プロンプトは幅と高さを配置に使います。  
例えば取得結果が 120 列・0 行なら、両者が扱う端末幅は 120 列、固定プロンプトの高さは 24 行です。  
Windows では画面バッファー全体の大きさではなく、従来と同じ表示ウィンドウの範囲から寸法を求めます。

## 移行失敗は行入力へ切り替え、復元失敗はエラーにする

raw モードへの移行は、保存、設定変更、必要なリサイズ通知登録を含む一連の処理として扱います。  
Linux の SIGWINCH 登録失敗も移行失敗です。  
途中で失敗したら、変更済みの項目だけを復元します。  
復元が不要または成功した場合に限り、既存の行入力処理へ切り替えます。  
行入力への切り替えでは既存と同様に初期値を適用しません。

復元に失敗した場合は、行入力に切り替えず `CPLAT_ERR_UNKNOWN` を返します。  
正常入力、EOF、キャンセル、メモリ不足などの終了経路も、復元が失敗した場合はこのエラーを優先します。  
編集用資源やロックの解放は、復元結果にかかわらず実行します。  
入力結果は成功が返った場合に利用する契約を維持します。

失敗した復元項目の保存値と状態は保持し、次回の入力開始前またはハンドル解放時に再度復元を試みます。  
一度の呼び出し内で無限に再試行しません。  
解放関数は戻り値を追加せず、復元を試みてから通常の資源解放を行います。  
OS が復元を拒み続けた場合の復元成功は保証せず、解放時の再試行失敗は戻り値では通知できません。

## 入力終了、入力失敗、待機終了を区別する

共通内部入力関数は `int` を返し、負の状態値を名前付きの定数で定義します。

Table: 端末入力の共通内部結果

| 内部結果 | 値 | 上位の扱い |
| --- | --- | --- |
| 入力バイト | 0〜255 | 既存のキー解釈と UTF-8 編集へ渡す |
| EOF | -1 | 入力終了として `CPLAT_ERR_EOF` を返す |
| リサイズ確認契機 | -2 | サイズを再確認して入力待ちを続ける |
| OS エラー | -3 | 復元を試み、`CPLAT_ERR_UNKNOWN` を返す |
| 短時間待ちのタイムアウト | -4 | 追加入力なしとして扱う。入力エラーにしない |

Linux の読み取りが返した EOF と、エラーによる読み取り失敗を分けます。  
EINTR は既存の再待機方針を維持し、リサイズ通知があれば上位へ通知します。  
50 ms の追加入力待ちでも、タイムアウトと OS エラーを区別します。  
エスケープ シーケンスの途中で起きた OS エラーも、未知のキーや単なる追加入力なしとして消費せず上位へ伝えます。

Windows は UTF-16 で入力し、既存の共有変換処理で UTF-8 バイト列へ変換します。  
変換済みの未消費バイトと保留 UTF-16 単位を共通状態で保持し、待機前に消費します。  
通常の入力待ちは 100 ms の待機タイムアウトをリサイズ確認契機として返し、エラーにはしません。  
エスケープ シーケンス判定用の 50 ms の待機終了は短時間待ちのタイムアウトとします。  
Windows のリサイズ追従は従来の定期的なサイズ再確認を使います。

## 利用者向け契約と永続的な説明を同期する

公開ヘッダー `prod/include/cplat/prompt/prompt.h` と `pinned_prompt.h` の入力関数に、端末入力エラーと復元失敗の戻り値を反映します。  
関連する書式付き・初期値付き入力関数も、同じ契約と一致させます。  
`docs/api-cheatsheet.md` の説明を照合し、戻り値や利用方針の記載に不一致があれば修正します。  
公開シンボルとシグネチャは変えないため、公開 mock の追加は行いません。

`docs/functional-spec/prompt.md` には、端末サイズが一部不明な場合の扱い、文字単位入力へ切り替えられない場合の行入力、入力失敗と端末復元失敗の通知を、利用側の振る舞いとして反映します。  
機能仕様には内部関数名、内部値、テスト手順を記載しません。  
既存の要件の変更として整理し、新たな独立機能として要件を重複追加しません。

共通状態の所有権と復元義務は私有ヘッダーの契約コメントに記載します。  
非自明な OS 仕様の根拠は、既存の `see: <URL>` を共通処理へ移し、追加の根拠が必要な箇所は一次資料を確認して記載します。  
生成された Doxygen 成果物は手動変更しません。

## 両 OS の対象テストで境界と失敗経路を確認する

ソース 1 本につき `TEST_SRCS` を指定するテスト ディレクトリは一つとします。  
既存の `promptLinuxTest` と `promptWindowsTest` は共通 OS 別実装のテストへ移行し、`promptPlatformTest` を共通ソースのテストとして追加します。  
`promptTest` と `pinnedPromptTest` は、共通インターフェイスの fake と失敗注入により上位への結果伝達を検証します。  
共通処理の動作を上位テストに重複して実装しません。

確認項目は次のとおりです。

- サイズ取得成功、全体失敗、片方の寸法だけ不正となる場合。
- TTY 判定と非 TTY の既存の行入力。
- raw モードの保存・変更・登録の各失敗、成功済み項目の復元、復元失敗後の状態保持と再試行。
- 正常終了、EOF、キャンセル、入力失敗と復元失敗の優先順位。
- Linux の SIGWINCH 登録・復元、通知消費、通常と固定を順に使った場合の通知残留防止。
- Windows の UTF-16 サロゲート、保留入力、100 ms の確認契機と 50 ms の短時間待ち。
- エスケープ シーケンスの途中での OS エラー。
- 既存の入力補完、横スクロール、固定領域の再描画、リサイズ時の表示。

Windows は MSVC、Linux は WSL の `OracleLinux8-Dev` にある GCC/make で、同じ作業ツリーを検証します。  
調査時点で両ツールと WSL からの作業ツリー参照を確認済みです。  
ビルドとテストは承認後に実行します。

Windows の対象コマンドは次を基本とします。

```powershell
make -C app/cplat/prod/libsrc
make -C app/cplat/test/src/libcplatTest/prompt/promptPlatformTest test
make -C app/cplat/test/src/libcplatTest/prompt/promptLinuxTest test
make -C app/cplat/test/src/libcplatTest/prompt/promptWindowsTest test
make -C app/cplat/test/src/libcplatTest/prompt/promptTest test
make -C app/cplat/test/src/libcplatTest/prompt/pinnedPromptTest test
make -C app/cplat doxy
```

Linux では WSL 内の `/mnt/d/Users/tetsuo/Local/repos/c-modernization-kit` を作業ディレクトリとし、同じライブラリ ビルドと対象テストを実行します。  
OS 専用テストが他方の OS で実行対象外になった結果は、その OS での検証成功の代用にしません。  
共通処理は Linux の条件網羅、Windows の行網羅と個別ケースの結果を確認します。  
ビルド後は対象範囲で内容のある `.warn` を確認します。  
framework や複数 app の全体テストは今回の局所検証には含めません。

公開契約と内部宣言の変更に対して cplat の Doxygen を生成し、警告と生成結果を確認します。  
新規ソースは clang-format、既存ソースの変更は git clang-format で整形を確認します。  
Markdown はファイルごとに `text_style_jp.py --dry-run` の結果を確認してから `--in-place` を実行します。

実端末での対話操作は、入力補完、端末リサイズ、終了後の端末復元を確認します。  
自動テストで確認した範囲と、実端末で確認できた範囲を分けて記録します。  
環境不足や操作手段の制約で未実施の項目があれば、完了した項目に含めず報告します。

## 受入条件

端末の OS 依存処理が共通実装に集約され、固定プロンプト内に同等の実装が残っていないことを確認します。  
合意したサイズ取得、移行失敗、入力エラー、復元失敗の振る舞いが両プロンプトで一致し、上記の局所検証で確認できることを受入条件とします。  
既存の補完と描画の動作を維持し、Linux と Windows の検証結果、警告、未実施項目を提示します。

実装・検証の完了後、元の `261012-cplat-prompt-completion-backlog.md` から解消した BL-001 を除き、残課題がなくなったことを記載します。  
見送りや未対策の残渣があれば、解消した BL-001 と混同せず別の残課題として記録します。  
ステージング、コミット、アンステージ、スタッシュは実施しません。
