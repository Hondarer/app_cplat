# ネットワーク (net) 機能仕様

## 概要

ネットワークは、IPv4 のソケット、エンドポイント、バイト オーダー変換を、Linux と Windows で共通の意味として提供します。

## 解決する課題

Linux と Windows では、ソケットの表現、初期化、終了、非ブロッキング設定、エラーの取得方法が異なります。  
システムのネットワーク定義を公開面へ露出すると、利用側もプラットフォームごとの定義と初期化順序に依存します。

送受信は指定した長さより短く完了することがあり、切断済みの接続への送信がプロセスへ影響する環境もあります。  
本機能は、これらの差を cplat の共通の意味へまとめます。

## ソケットとエンドポイント

共通のソケット ハンドルは、対応するプラットフォームのソケットを可逆に保持します。  
無効なハンドルも共通の値として判定できます。

エンドポイントは IPv4 アドレスとポートを保持します。  
数値形式の IPv4 アドレスとホスト名のどちらからも生成でき、名前解決の失敗は他のソケット エラーと区別します。  
数値形式の IPv4 アドレスから生成する場合も、プラットフォームで必要な初回初期化を行い、初期化の失敗とアドレス形式の不正を区別して通知します。

## バイト オーダー

16 ビット、32 ビット、64 ビットの符号なし整数を、ホスト バイト オーダーとネットワーク バイト オーダーの間で変換できます。  
変換はホストのバイト オーダーを判定せずに行い、結果のバイト列は常にネットワーク バイト オーダーになります。

## 初期化と設定

ネットワーク機能は、初回使用時にプロセスで必要な初期化を一度だけ行います。  
利用側は、個々のネットワーク操作より前に初期化を呼び分ける必要がありません。

ソケットの再利用、非ブロッキング、送信タイムアウト、受信タイムアウト、送受信バッファーなどを、用途ごとの設定として変更できます。

## 送受信と待機

指定した長さを扱う送受信は、途中までしか処理されなかった場合に残りを継続します。  
接続の終了、タイムアウト、再試行が必要な状態、その他の失敗は区別して通知します。

複数ソケットの待機は、受信可能なソケットの集合と、タイムアウトした結果を返します。

Linux で切断済みの接続へ送信した場合も、プロセスへ終了シグナルを配信させず、送信の失敗として利用側へ返します。

受信方向だけを停止する操作は、Linux ではソケットを保持し、Windows ではソケットを閉じます。  
ソケットを閉じた場合は、利用側が閉じたソケットを再利用しないよう、保持している値を無効な値へ変更します。

## 適用範囲外

- IPv6
- TLS などの暗号化通信
- DNS キャッシュ
- イベント ループと非同期 I/O の実行基盤
- メッセージ境界を持つ上位プロトコル

## 前提と制約

指定した長さを完了まで処理する送受信は、接続型ソケットを対象とします。

非ブロッキング状態またはタイムアウトを使用する場合、利用側は再試行が必要な結果と終了を区別する必要があります。

ホスト名の解決結果が複数ある場合に、利用側が使用するアドレスの選択方針までは定めません。

同じソケットに対する複数の処理を同時に行う場合は、利用側が処理を直列化する必要があります。
