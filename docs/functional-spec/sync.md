# 同期 (sync) 機能仕様

## 概要

同期は、スレッドの生成と待ち合わせ、プロセス内の同期、プロセス横断の同期、待機時間の指定、アトミック操作を提供します。

## 解決する課題

スレッドと同期オブジェクトは、Linux と Windows で生成、待機、破棄、失敗の意味が異なります。  
プロセス内で有効な同期と、複数プロセスで共有する同期も別の手続きになります。  
ロックを取らずに共有する値の読み書きも、コンパイラごとに手段が異なり、標準 C の `<stdatomic.h>` は MSVC の C17 モードで利用できません。

本機能は、同期の有効範囲と読み書きの性質を選べる共通の機能として提供します。

## 同期の種類

プロセス内の同期は、相互排他、読み書きロック、条件待機を提供します。  
読み取りが多く書き込みが少ない共有データでは、読み書きロックによって複数の読み取りを並行できます。

プロセス横断の同期は、相互排他と読み書きロックを提供します。  
同じ識別子を指定したプロセスは、同じロックを開きます。

## アトミック操作

アトミック操作は、ロックを取らずにスレッド間、または共有メモリを介してプロセス間で読み書きする値に使います。  
値は操作専用の型に格納し、通常の代入や参照では読み書きできないようにします。

各操作は、メモリ順序を選べます。

| メモリ順序 | 保証すること |
|---|---|
| 順序を守らない軽量な操作 | 値の読み書きが不可分であることと、最適化で省略されないこと |
| 取得順序と解放順序 | 解放順序で書いた値を取得順序で読んだ側が、書き込みの前に行われた読み書きを観測できること |
| 逐次一貫順序 | すべてのスレッドから、逐次一貫順序の操作が同じ順に観測されること |

Table: アトミック操作のメモリ順序と保証内容

アトミック操作は待機を伴わず、失敗を返しません。

## 待機とタイムアウト

待機には、無期限、待機なし、ミリ秒単位の期限を指定できます。  
期限までに取得できなかった場合と、待機せずに取得できなかった場合は異なる結果として通知します。

OS による一時的な中断は、利用側から通常の同期結果として観測されないように扱います。

## プロセス横断ロックの受け渡し

開いているプロセス横断ロックは、別のプロセスへ渡せるディスクリプターに変換できます。  
受け取った側は、ディスクリプターから同じロックを開きます。

ディスクリプターの内容が破損している場合は、ロックを開かずに破損を通知します。  
受け渡し形式の版が異なる場合もロックを開かず、破損とは区別して版の不一致を通知します。  
利用側は、書き出し前に必要なディスクリプターの長さを取得できます。

## 適用範囲外

- スレッド プールとタスク スケジューリング
- スレッドの優先度とプロセッサ affinity
- 再入可能な相互排他
- デッドロックの検出と回復
- 構造体など、アトミック操作の専用型より大きな値の不可分な読み書き

## 前提と制約

同期オブジェクトを破棄する前に、他のスレッドまたはプロセスが使用していないことを利用側が保証する必要があります。

スレッドの切り離しは、同じスレッドに対して一度だけ行う必要があります。

ファイルを複数のプロセスから開けること自体は排他制御を意味しません。  
共有データの一貫性が必要な場合は、すべての参加プロセスが同じロックを使用する必要があります。

## 選択の指針

| 状況 | 使用する同期 |
|---|---|
| 単一プロセス内の排他 | プロセス内の相互排他 |
| 単一プロセス内で読み取りが多い共有データ | プロセス内の読み書きロック |
| 条件の成立まで待機 | 条件待機とプロセス内の相互排他 |
| 複数プロセス間の排他 | プロセス横断の相互排他 |
| 複数プロセス間で読み取りが多い共有データ | プロセス横断の読み書きロック |
| 停止要求などのフラグ、計数、変化の検知に使う世代番号 | アトミック操作 |
