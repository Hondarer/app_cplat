# C ランタイム抽象 (crt) 機能仕様

## 概要

C ランタイム抽象は、境界検査を伴う文字列処理と、Linux と Windows で意味をそろえたパス、ファイル、環境、時刻の操作を提供します。

## 解決する課題

標準 C ライブラリと OS のファイル操作は、Linux と Windows で文字コード、パス区切り、ファイル共有、ファイル位置、関数名、失敗の通知方法が異なります。  
同じ処理を両方で使用するには、利用側が差を吸収しなければなりません。

標準機能の一部は、書き込み先の容量を受け取らない、変換失敗を通知しない、切り詰めを検出しにくいという性質を持ちます。  
本機能は、これらの差と安全上の不足を共通の操作として扱います。

## 境界検査を伴う処理

文字列を出力先へ書き込む処理は、出力先の容量を必須条件として受け取り、範囲外へ書き込みません。  
出力先が不足する場合は、切り詰めまたは容量不足を、完全な成功と区別します。

文字列から整数への変換は、入力全体を変換できることと、値が結果の型で表現できることを確認します。  
不正な文字列を数値の 0 として扱いません。

### ファイル記述子集合

ファイル記述子集合へ値を追加する場合は、プラットフォームが定めた集合容量の範囲を検査します。  
容量を超える追加によって集合領域を破壊する処理は継続しません。  
追加できなかった値を無視して、監視対象が不足したまま処理を継続することもしません。

## パスの扱い

パスは、対応するすべてのプラットフォームで UTF-8 として受け取ります。  
Windows では入力の `/` と `\` を区切りとして受け付け、利用側へ返す区切りは `/` に統一します。

外部から得たパスも、明示的に同じ区切りへ正規化できます。  
パスから構成要素を取り出す処理は、入力に含まれるどちらの区切りも認識します。

## ファイル操作

ファイルを開く場合は、Linux と Windows で同じ共有可能な既定動作を提供します。  
ファイル位置は 64 ビットで表現し、2 GiB を超える位置を扱えます。

一度の低レベル読み書きで扱える長さは、対応するすべてのプラットフォームで同じ結果を保証できる範囲に限定します。  
指定した長さの全体を一度に処理できない場合は、実際に処理した長さを返します。

ファイルの更新日時は、サブ秒を含む共通の時刻表現で取得および設定できます。

## その他の差異吸収

環境変数は、存在の確認、値の取得、現在のプロセスに対する設定を行えます。  
設定は現在のプロセスにだけ反映します。

時刻の分解と文字列の分割は、並行呼び出しが共有状態を上書きしない形で提供します。

大文字小文字を無視する比較は ASCII の範囲だけを同一視し、ロケールの設定によって結果を変えません。

## 適用範囲外

- 両プラットフォームで同じ意味を持ち、境界検査の不足もない標準機能の置き換え
- ディレクトリ内の項目の列挙
- UTF-8 と Windows のワイド文字列以外の一般的な文字コード変換
- ロケールに依存する文字列比較と並べ替え
- 一度の呼び出しで任意長の低レベル読み書きを必ず完了すること

## 前提と制約

パスとして渡す文字列は UTF-8 である必要があります。  
現在のコード ページで表したナロー文字列の動作は保証しません。

パスの長さは、cplat が対応対象として定める最大パス長を上限とします。

環境変数の変更は、親プロセスまたはすでに起動している別のプロセスへ反映されません。

## 選択の指針

パスが固定されている場合は、そのパスを直接指定する処理を使用します。  
連番や日時からパスを組み立てる場合は、パスの生成とファイル操作を一つにまとめた処理を使用します。

ファイルを順に読み書きする場合は本機能を使用し、ファイルの領域をアドレス空間から直接参照する場合はメモリ マップド ファイルを使用します。
