# 圧縮 (compress) 機能仕様

## 概要

圧縮は、メモリ上のバイト列を圧縮し、元のバイト列へ展開する機能です。  
生成した圧縮データは、Linux と Windows の間で相互に利用できます。

## 解決する課題

プラットフォームごとに利用できる圧縮機能と既定の出力形式が異なります。  
形式を固定しなければ、一方のプラットフォームで圧縮したデータを、他方で展開できません。

raw DEFLATE は展開後の長さを含まないため、利用側が元の長さを別の情報として管理すると、データとの対応を取り違える可能性があります。

## 圧縮データの形式

圧縮データは、次の形式です。

```text
[展開後の長さ: 64 ビット符号なし整数、ネットワーク バイト オーダー] [raw DEFLATE データ]
```

圧縮本体は RFC 1951 の raw DEFLATE とします。  
展開後の長さを先頭へ含めるため、利用側は長さを別に管理する必要がありません。

展開時は、圧縮データに含まれる長さと出力先の容量を比較します。  
出力先が不足する場合は展開を完了せず、容量不足として通知します。  
圧縮データが破損している場合、途中で打ち切られている場合、または展開された実際の長さが先頭の長さ情報と一致しない場合は、宣言された長さを超えて書き込まず、出力長も更新しないままデータの破損として通知します。

展開後の長さが 4 GiB 以上の場合は、圧縮も展開も行わず、上限超過として通知します。  
4 GiB 未満の有効なデータは、対応するすべてのプラットフォームで一括して圧縮および展開できます。

## メモリ不足の通知

圧縮または展開の準備中と処理中に必要なメモリを確保できない場合は、処理を中止してメモリ不足を通知します。  
この通知は Linux と Windows で共通とします。

## 適用範囲外

- 入力または出力を分割して処理するストリーミング圧縮
- 圧縮レベルの選択
- gzip または zip のコンテナー形式
- ファイルを直接入出力する圧縮

## 前提と制約

展開後の長さの欄は 64 ビットです。  
扱える展開後の長さは 4 GiB 未満です。  
先頭が 32 ビットの長さ欄だった圧縮データは対象外です。

出力先の領域は利用側が用意します。

本機能の圧縮データは、先頭に cplat 固有の長さ情報を持ちます。  
raw DEFLATE だけを受け取る機能へ、圧縮データ全体をそのまま渡すことはできません。
