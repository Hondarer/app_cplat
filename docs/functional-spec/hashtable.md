# ハッシュ テーブル (hashtable) 機能仕様

## 概要

ハッシュ テーブルは、キーに対応する値を保持する表を、cplat が確保する領域または利用側が用意する領域へ構築する機能です。  
固定長と可変長のキーおよび値、保存後の再接続、変更の観測、遅延削除を扱います。

## 解決する課題

C でハッシュ テーブルを用意する場合、利用側はキーと値の格納、容量不足、削除、保存可能な配置、変更の観測を用途ごとに設計する必要があります。  
可変長データでは、格納領域の断片化と連続空き領域の不足も扱わなければなりません。

複数の読み取り側が表の変更を観測する用途では、値の有無だけでなく、削除された時点と再利用できる時点を区別する必要があります。  
本機能は、これらを表の性質として提供し、利用側にはデータ形式、容量方針、変更検知の粒度を選択させます。

## キーによる値の管理

追加は、同じキーが存在する場合に重複を通知します。  
更新は、対象のキーが存在しない場合に未登録を通知します。

追加と更新を一つの操作として行うこともでき、その場合は新規追加と既存更新のどちらを行ったかを返します。  
検索と削除は、対象のキーが存在しない結果を他の失敗と区別します。

## キーと値の格納形式

固定長バイナリ、固定長文字列、可変長文字列を、キーと値について個別に選べます。  
固定長文字列は、格納領域の長さを固定したまま、終端までを文字列として扱います。

可変長文字列は、レコードとは別の格納領域へ内容を保持します。  
取得した可変長データへの参照は、そのデータの更新、削除、領域の圧縮まで有効です。

## 領域の所有と再接続

表の領域は、cplat に確保させるか、利用側が用意できます。  
利用側が用意する場合は、表の管理情報とレコード、可変長データを同じ領域または別の領域へ配置できます。

保存した領域へ再接続する場合は、表の形式、領域の長さ、参照範囲、指定した格納形式との一致を検査します。  
検査に合格しない領域は表として扱いません。  
保存形式の版の不一致は、領域の破損と区別して通知します。

保存形式はポインターを含まず、別のアドレスへ配置した同じ領域へ再接続できます。

## 容量方針

固定容量では、生成後にレコード数と格納領域を拡張しません。  
容量を超えた追加は、既存の内容を変更せずに容量不足を通知します。

自動拡張では、必要に応じてレコード領域、キー領域、値領域を拡張します。  
利用側はそれぞれに上限を指定でき、上限に達した場合は追加を完了しません。

生成時に内容が確定する表では、指定したレコード番号へ直接配置できます。  
直接配置したレコード番号は、保存と再接続の後も維持します。

## 削除の観測と回収

遅延削除を使用する場合、削除したレコードは「削除中」の状態となり、直ちに空きレコードへ戻りません。  
読み取り側は削除中のレコードを走査し、削除を観測できます。

削除の世代を進めると、所定の世代を経た削除中レコードを回収できます。  
回収後のレコードは新しい値へ再利用できます。

## 変更の検知と走査

表全体または個々のレコードについて、変更時刻と世代を保持できます。  
利用側は必要な粒度を生成時に選択します。

レコード番号による走査では、使用中、削除中、空きなどの状態を選べます。  
表が保持する現在件数は、全容量を走査せずに取得できます。

## 可変長領域の圧縮

可変長領域では、空きの合計が足りていても、必要な長さの連続領域がない場合があります。  
この場合は連続領域の不足を通知し、自動的には既存データを移動しません。

利用側が圧縮を指示すると、使用中の可変長データを再配置して連続空き領域を増やします。  
圧縮によって、以前に取得した可変長データへの参照は無効になります。

## 固定長値の配置境界

固定長値は、指定がない場合に隙間なく配置します。  
型付きの参照として使用する場合は、その型が必要とする 2 の累乗の配置境界を指定できます。

指定した場合は、各固定長値の先頭がその境界に配置されることを保証します。

## 適用範囲外

- キーまたは値の内容に応じた独自の比較関数
- 保存領域のエンディアン変換
- 異なるレコード形式への自動移行
- 複数のスレッドまたはプロセス間の排他制御
- 可変長データへの参照を、更新または圧縮後も維持すること

## 前提と制約

同じ表を複数の実行主体から変更する場合は、利用側が同期を行う必要があります。

保存した表の読み戻しは、同じエンディアン、ビット幅、配置規則を持つ環境を前提とします。

利用側が用意する領域は、指定した容量と配置境界を満たし、表の利用が終わるまで有効である必要があります。

直接配置では、同じレコード番号へ重複して配置せず、表が要求する識別情報を利用側が一貫して与える必要があります。

## 選択の指針

| 状況 | 容量と領域の方針 |
|---|---|
| 件数が実行時まで決まらない | 自動拡張 |
| 件数が設計時に決まり、領域の所有を任せられる | cplat が確保する固定容量 |
| 共有メモリまたはメモリ マップド ファイルへ配置する | 利用側の領域へ構築する固定容量 |
| 生成時に内容が確定し、レコード番号を維持して配布する | 直接配置して保存し、利用側で再接続 |
