# サービス (service) 機能仕様

## 概要

サービス機能は、Linux の systemd デーモンと Windows のサービス (Service Control Manager) を共通の構成で登録、解除、常駐実行、およびフォアグラウンド実行するための機能です。  
起動・動作・停止のライフサイクル、停止要求の待機、OS イベントおよび設定再読込の通知、状態テキストの報告、異常終了時の自動再起動、および生存監視を提供します。

## 解決する課題

Linux の systemd と Windows の Service Control Manager は、サービスの登録形式、起動完了や停止開始の通知手順、電源・セッション・シャットダウン前イベントの受信経路、設定再読込の契機、および異常終了時の自動再起動設定が大きく異なります。  
利用側のサービス本体は、これらの OS 固有の差異に煩わされず、初期化・メイン ループ・停止処理とイベント応答の記述に専念できる必要があります。

また、常駐サービスはデバッグや開発時にフォアグラウンドのコンソール プロセスとして同じライフサイクルで実行できる必要があり、停止要求はコンソールからの割り込みと OS サービス マネージャーからの停止制御を同じ仕組みで検知できる必要があります。

## サービスの登録と解除

サービスの登録では、実行ファイルのパス、起動引数、説明文、異常終了時の自動再起動設定、Linux 向けの生存監視時間と OOM 保護、および Windows 向けのシャットダウン前猶予時間を OS のサービス マネージャーへ反映します。  
登録オプションが省略またはゼロ初期化された場合は、すべての項目に安全な既定値を適用します。

登録および解除には管理者権限 (Linux は root、Windows は管理者) が必要です。  
権限が不足している場合、サービス機能自身は権限昇格や再実行を行わず、権限不足を返します。  
対話的な権限昇格が必要な場合は、利用側のコマンド ライン層が [実行時支援 (runtime)](runtime.md) の権限昇格機能を使用します。

Linux で自動再起動が有効な場合は、再起動遅延と起動回数制限の集計期間・上限回数の整合を事前に検査し、制限に永遠に到達できない設定を拒否します。  
Linux の OOM 保護が有効な場合は、カーネルの OOM 保護設定に加えて、対応する systemd バージョンでのみユーザー空間 OOM 保護設定を出力します。

## ライフサイクルと停止抽象

サービスの実行は、初期化、起動完了通知、メイン ループ、停止開始通知、停止処理の順に進めます。  
初期化が失敗した場合は起動を中断し、メイン ループと停止処理を実行しません。  
メイン ループが失敗した場合は、後始末のため停止処理を実行したうえで、最初に失敗した段階の終了コードを返します。

停止要求の待機、即時判定、および停止要求の発行はスレッド セーフであり、OS サービス マネージャーからの停止通知、コンソールからの割り込み、および利用側からの明示的な停止要求を単一の停止抽象へ集約します。  
停止待機は、即時判定、有限時間の待機、および無期限待機に対応し、停止要求の到達と時間経過を明確に区別して返します。

コンソール モードでは、OS サービス マネージャーへ接続せずにフォアグラウンドで同じライフサイクルを実行し、コンソールからの終了要求を停止抽象へ接続します。

## OS イベント、設定再読込、および生存監視

電源のサスペンド・復帰、ユーザー セッションのログオン・ログオフ、およびシステム シャットダウン前の猶予通知は、動作中段階に限って利用側へ配送します。  
Linux では、サスペンドおよびシャットダウン前の処理猶予を確保するため、遅延抑止ロックを取得してイベント配送後に解放します。  
D-Bus に接続できない環境 (コンテナーなど) では、該当するイベント監視だけを無効化してサービス本体を継続します。

設定再読込は、Linux では `SIGHUP`、Windows ではパラメーター変更制御を契機に、動作中段階に限って利用側へ配送します。  
Linux では、スレッド生成前に事前準備を呼び出して `SIGHUP` をブロックしておく必要があります。  
再読込処理が未登録のサービスでは、Linux のユニット設定へ再読込コマンドを出力せず、`SIGHUP` を受信しても警告を記録して無視します。

Linux で OS サービス マネージャーから生存監視が要求されている場合は、メイン ループが停止待機を呼び出し続けている間だけ生存通知を送信します。  
停止時にイベント監視スレッドが上限時間内に終了しない場合は、解放済み資源への参照を防ぐためプロセスを異常終了させます。

## 診断トレース

サービス層の内部で非同期に発生する診断情報 (コールバックの失敗、OS 通知の失敗、イベント監視の警告など) は、利用側が指定したトレース出力先へ記録します。  
トレース出力先の生成・開始・停止・破棄の所有権は利用側にあります。  
トレース出力先が指定されていない場合は、診断トレースの出力を省略します。

## 前提と制約

- 1 プロセスにつき同時に実行できるサービスは 1 つです。サービス状態はプロセス単位で管理します。
- Linux の常駐実行では、スレッド生成およびトレース開始より前に、単一スレッド段階で事前準備を呼び出す必要があります。
- OS イベントおよび設定再読込のコールバックは、メイン ループとは別のスレッドから呼び出されます。共有データへのアクセスは利用側で同期する必要があります。
- Linux でサービス登録・解除を行う場合は、systemd が稼働する環境を前提とします。

## 適用範囲外

- 1 プロセス内での複数サービス インスタンスの同時実行
- コマンド ライン引数の解析、サブコマンドの振り分け、および `main` 関数の提供
- サービス登録・解除時の自動権限昇格 (UAC や `sudo` の起動)
- サービスの一時停止 (pause) および再開 (continue)
- Windows サービス起動中・停止中の進捗チェックポイントの動的更新
