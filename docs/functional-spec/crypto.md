# 暗号 (crypto) 機能仕様

## 概要

暗号は、バイト列の認証付き暗号化と復号、パスフレーズからの鍵導出、暗号論的乱数の取得を提供します。  
暗号化したデータは、Linux と Windows の間で相互に利用できます。

## 解決する課題

暗号化だけでは、暗号文が改ざんされたことを検出できません。  
同じ鍵とノンスの組み合わせを再利用した場合や、予測可能な値を鍵やノンスに使用した場合も、安全性が失われます。

プラットフォームごとに異なる暗号機能を利用側が直接扱うと、初期化、形式、失敗時の扱いが分かれます。  
本機能は、アルゴリズムと受け渡し形式を固定し、利用側が安全性に関わる選択を誤る余地を限定します。

## 暗号化の形式

暗号化の結果は、次の形式です。

```text
[暗号文: 平文と同じ長さ] [GCM 認証タグ: 16 バイト]
```

暗号化だけを行い、認証タグを省略する形式は提供しません。  
復号時は認証タグを検証し、暗号文または追加認証データが変更されている場合は復号を成功させず、認証の失敗を他の失敗と区別して通知します。  
認証に失敗した場合、出力先の内容は平文として使用できません。

ノンスは 12 バイトで、次の形式です。

```text
[セッション識別子: 4 バイト] [連番: 4 バイト] [予約領域: 4 バイト]
```

セッション識別子と連番は利用側が指定します。  
利用側は、同じ鍵に対して同じ組み合わせを再利用しないよう管理します。

## 鍵の導出と乱数

パスフレーズから、暗号化に使用する固定長の鍵を導出できます。  
導出した鍵の強度は、元のパスフレーズの強度を超えません。

鍵、セッション識別子など、推測されてはならない値の生成に使用できる暗号論的乱数を取得できます。

## 適用範囲外

- AES-256-GCM と SHA-256 以外のアルゴリズム選択
- 公開鍵暗号と電子署名
- 鍵の保管、配送、失効
- セッション識別子と連番の採番および永続化
- TLS などの通信プロトコル

## 前提と制約

利用側は、同じ鍵に対して同じノンスを再利用してはなりません。

入力の長さは、対応するすべてのプラットフォームで同じ結果を保証できる範囲に限定します。  
平文、追加認証データ、および鍵導出のパスフレーズがこの範囲を超える場合は、処理を行わずに出力先を変更しないまま範囲超過として通知します。

パスフレーズは、必要な強度を持つ値を利用側が用意します。
