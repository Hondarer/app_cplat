# 実行時支援 (runtime) 機能仕様

## 概要

実行時支援は、プログラムが自分の実行環境を調べ、子プロセスを扱い、終了処理を管理し、実行時に機能を差し替え、機密データを保持するメモリをロックし、プロセスとスレッドの実行優先度を制御し、スタック サイズの上限を引き上げるための機能群です。

## 解決する課題

ホスト名、実行ファイル、共有モジュールの位置、プロセスの生成と権限昇格は、プラットフォームごとに取得方法と結果が異なります。  
終了処理と終了要求の捕捉も、通常終了、外部からの要求、強制終了で保証できる範囲が異なります。

実行環境ごとに機能を差し替える場合は、設定の誤りによってプログラム全体が起動できなくなることを避ける必要があります。  
機密データを保持する場合は、対象メモリが補助記憶へ書き出されないよう制御する必要があります。

実行優先度は、Linux と Windows で制御できる軸と単位が異なります。  
Linux はスケジューリング ポリシー、nice 値、I/O 優先度などをスレッドごとに持ち、Windows は優先度クラスなどをプロセスごとに、相対優先度をスレッドごとに持ちます。  
優先度を上げる操作は権限を必要とし、権限が不足した場合に呼び出し元がそれを判別できる必要があります。

Linux のメイン スレッドのスタックは、起動元から引き継いだ資源上限 (多くの環境で 8 MiB) を超えて伸びず、超えるとプロセスが強制終了します。  
深い再帰や大きな局所変数を使うプログラムは、起動元の設定に依存せず、自プロセスに許された範囲で上限を引き上げる必要があります。

## ホストとモジュールの情報

ホスト名は、OS が保持する DNS ホスト名を UTF-8 で返します。  
完全修飾ドメイン名であることは保証しません。

指定した関数を含むモジュールの絶対パスと、そのファイル名を取得できます。  
実行ファイル本体の絶対パスも、モジュールの位置とは別に取得できます。

## プロセスと権限昇格

子プロセスを起動し、完了を待って終了状態を取得できます。  
待機を継続できない場合は子プロセスを強制終了できます。

Windows では、現在の権限が不足する場合に、自分自身を権限昇格して起動できます。  
Linux では、現在の実効ユーザーが必要な権限を持たない場合に、cplat 自身による権限昇格は行いません。

権限昇格したプロセスの結果は、一時的なファイルを介して呼び出し元へ返せます。  
この経路は、コンソールへの出力に依存せず、結果の種類とメッセージを受け渡します。

権限昇格したプロセスの標準出力と標準エラー出力は、プロセスの実行中に呼び出し元へ受け渡せます。  
呼び出し元は受け取った出力を自分の標準出力と標準エラー出力へ書き込むか、利用側が指定した処理へ渡します。  
呼び出し元の出力がリダイレクトされている場合も、権限昇格したプロセスの出力はそのリダイレクト先へ届きます。  
標準出力と標準エラー出力の間の出力順序は保証しません。  
権限昇格したプロセスへ標準入力は受け渡しません。権限を持たないプロセスから、権限昇格したプロセスを操作できないようにするためです。

## プロセスとスレッドの識別

実行中のプロセスと、その中で実行中のスレッドを、診断で識別するための数値をそれぞれ取得できます。  
ログの出力行やロック ファイルの名前に記録し、複数のプロセスやスレッドが混在する記録を後から切り分ける用途を想定します。

いずれの数値も OS が割り当てた識別子です。  
プロセスの識別子は同時に存在するプロセスの間で、スレッドの識別子は同時に存在するスレッドの間で、それぞれ一意です。  
終了したプロセスやスレッドの識別子は、OS が後続のプロセスやスレッドへ再び割り当てる場合があります。

子プロセスの起動、完了待ち、強制終了には、プロセスの識別子ではなく、起動時に得られるプロセスの参照を使用します。  
スレッドの生成、待機、切り離しには、スレッドの識別子ではなく、同期機能が提供するスレッドの操作を使用します。

## 終了処理

登録した後処理は、通常のプロセス終了時に登録順序に従って実行します。  
cplat が終了理由を保持している場合は、その理由を後処理へ通知します。

捕捉可能な終了要求は、登録した処理へ通知します。  
強制終了、プロセスの異常終了、OS が捕捉を許可しない終了では、後処理の実行を保証しません。

継続が危険な状態を検出した場合は、ビルド構成によらず、検出した位置を標準エラー出力へ出力してプロセスを異常終了させます。  
異常終了の前に、利用側が登録した処理を登録の逆順で呼び出します。利用側は、この処理で異常終了の記録などを行えます。  
登録した処理から異常終了を取り消すことはできません。  
異常終了では、通常終了時の後処理を実行しません。

## 実行時の機能差し替え

設定に、対象の機能、読み込むモジュール、解決するシンボルを指定できます。  
解決に成功した場合は、利用側がその参照先を使用できます。

設定ファイルがない場合、必須情報が不足する場合、未知の項目がある場合、型が一致しない場合、解決に失敗した場合は、その差し替えを適用しません。  
差し替えを適用できないことによって、設定を使用しない通常の起動を妨げません。

## メモリ ロック

自プロセスの指定したメモリ範囲を、OS が許可する範囲でページ アウトの対象外にできます。  
必要なページを先に物理メモリへ割り当てた上でロックすることもできます。

ロックを解除すると、対象範囲は通常のページ管理へ戻ります。

## 実行優先度

実行優先度は、Linux と Windows それぞれに特化した API で、軸ごとに設定・取得します。  
選択値は cplat 独自の値で指定し、利用側は OS のヘッダーを必要としません。

| OS | 対象の単位 | 軸 |
| --- | --- | --- |
| Linux | スレッド | スケジューリング ポリシーと静的優先度、fork 時の既定値への復帰、デッド ライン スケジューリング、nice 値、I/O 優先度、CPU 使用率クランプ |
| Windows | プロセス | 優先度クラス、メモリ優先度、電力スロットリング、優先度ブースト、バックグラウンド処理モード (自プロセスのみ) |
| Windows | スレッド | 優先度クラス内の相対優先度 |

Table: OS ごとの実行優先度の軸

対象は ID で指定し、0 は自分 (Linux は呼び出しスレッド、Windows は自プロセスまたは呼び出しスレッド) を表します。  
Linux で PID を指定すると、そのプロセスのメイン スレッドだけが変わります。  
新しいスレッドは作成元スレッドの値を引き継ぐため、スレッドを作成する前に変更すると、以降に作成するスレッド全体に及びます。

権限が不足する場合は、権限不足を示す結果コードを返し、OS のエラーの詳細も取得できます。  
Windows で特権を持たずにリアルタイムの優先度クラスを指定すると、OS は失敗を返さずに 1 段低いクラスを設定します。cplat はこの格下げを検出して元のクラスへ戻し、権限不足として通知します。

OS が機能に対応しない場合は、非対応を示す結果コードを返します。  
Windows のバックグラウンド処理モードをすでにモード中に開始した場合と、モード外で終了した場合は、エラーではない省略として通知します。

## スタック サイズの上限

Linux で、自プロセスのスタック サイズの資源上限を取得し、特権を必要としない最大値まで引き上げます。  
引き上げは、呼び出した時点からメイン スレッドのスタックの拡張に適用されます。  
すでに最大値の場合は、エラーではない省略として通知します。

引き上げは、次の範囲には及びません。

- 既存のスレッドと、以降に作成するスレッドのスタック
- 起動時の上限から決まる、メイン スレッドのスタックと他のメモリ配置との間隔

引き上げた上限は、以降に起動する子プロセスへ引き継がれます。

## 適用範囲外

- 完全修飾ドメイン名の解決
- 標準入出力のリダイレクトと子プロセスとの対話 (権限昇格したプロセスの出力の受け渡しを除く)
- Linux での権限昇格手段の提供
- 強制終了またはクラッシュ時の後処理保証
- 差し替える機能の既定実装の提供
- 他のプロセスのメモリのロック
- プラットフォーム共通の実行優先度の抽象化
- Linux の autogroup の nice 値、cgroup の CPU と I/O の重み、CPU アフィニティの制御
- Windows の非公開 API による I/O 優先度、CPU アフィニティと CPU セット、スレッド単位のバックグラウンド処理モードの制御
- 実行優先度を変更できるかの事前確認
- 特権によるスタック サイズの資源上限の最大値の引き上げ
- 起動時から上限を適用するための自プロセスの再起動
- Windows のスタック サイズの変更

## 前提と制約

権限昇格したプロセスから結果を受け取る場合は、呼び出し元と昇格後のプロセスが同じ結果ファイルへアクセスできる必要があります。

実行時の機能差し替えを使用する場合、利用側は差し替えが適用されない場合の通常の処理を保持する必要があります。

差し替えた機能から同じ差し替え対象を再帰的に呼び出す構成の動作は保証しません。

メモリ ロックの上限と必要な権限は OS の設定に従います。  
要求した範囲をロックできない場合は、上限または権限の不足として通知します。

実行優先度を上げる操作に必要な権限は OS の設定に従います。  
Linux では、権限不足の原因 (ケーパビリティ、資源上限、cgroup のリアルタイム帯域) を区別できません。

プロセスとスレッドの ID は終了後に再利用されるため、利用側は指定した ID が意図した対象を指すことを保証する必要があります。

Linux の I/O 優先度は、I/O スケジューラーが対応する場合にだけ効果があります。

スタック サイズの上限の引き上げをメイン スレッド以外で必要とする場合、利用側はスレッドの作成時にスタック サイズを指定する必要があります。  
アドレス空間配置のランダム化が無効な環境では、引き上げ後もメイン スレッドのスタックは約 128 MiB を超えて伸びません。
