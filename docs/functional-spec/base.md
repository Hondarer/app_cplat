# 基盤 (base) 機能仕様

## 概要

基盤は、cplat の各機能が共通して使用する成否、詳細エラー、実行環境の差の表現を提供します。  
利用側は、元となる標準機能や OS ごとに異なる表現を、共通の方法で判定できます。

## 解決する課題

C の標準機能と OS の機能は、失敗の通知方法と詳細値の名前空間が統一されていません。  
利用側が生の値を扱うと、機能ごとに異なる成否判定と、プラットフォームごとの分岐が必要になります。

ビルド対象の OS、アーキテクチャー、コンパイラを表す定義も処理系ごとに異なります。  
各機能が個別に判定すると、同じ環境を異なる条件で扱う可能性があります。

基盤は、これらを cplat 共通の表現へまとめます。

## 共通の結果

成功は一つの値で表し、失敗は成功以外の分類済みの値で表します。  
要求を受け付けたものの条件により適用しなかった結果は、成功および失敗と区別します。

分類済みの結果は、引数と状態、資源、入力解析、制御、データの検証など、利用側が次の処理を判断するための粒度を持ちます。  
データの検証の失敗では、認証の失敗とデータの破損または形式不一致を区別します。  
OS 固有の詳細値を、共通の結果として直接扱いません。

結果の値は、既存の利用側とのバイナリ互換性を維持します。  
値の配置範囲そのものには意味を持たせず、個々の分類によって判定します。

## 詳細エラーと共通の原因

OS 由来の詳細は、値の名前空間、対応する共通結果、生の値を一つの情報として保持します。  
値の名前空間を保持することで、同じ数値を持つ異なる種類のエラーを区別します。

利用側が OS 固有の値を比較しなくても済むように、対象の不存在、アクセス拒否、再試行の必要、接続拒否などを共通の原因として判定できます。

詳細を扱う機能は、明示的な返却先と現在のスレッドの直前値へ同じ内容を記録します。  
成功時と、OS 由来の詳細を持たない失敗時は、以前の詳細が誤って参照されないよう直前値をクリアします。

## エラーの文字列化

共通の結果は、分類を識別できる文字列へ変換できます。  
OS 由来の詳細は、その名前空間に対応する人が読めるメッセージへ変換できます。

文字列の生存期間やプラットフォームごとの取得方法の差は、利用側へ露出しません。

## ビルド環境の識別

OS、アーキテクチャー、コンパイラは、cplat が正規化した環境情報で識別できます。  
Windows のシステム定義は、取り込み順序によって意味が変わらない共通の条件で利用できます。

## 共有ライブラリのライフサイクル

共有ライブラリは、ロード時の初期化とアンロード時の解放を、Linux と Windows で同じライフサイクルとして扱えます。  
ロードとアンロードの処理中でも使用できる診断出力を提供します。

## 適用範囲外

- 32 ビット環境への対応
- 例外による失敗通知
- OS 固有の詳細値だけを、由来を示さずに受け渡すこと
- 機能カテゴリごとに独立した結果体系
- 対応対象外の OS、アーキテクチャー、コンパイラの識別

## 前提と制約

cplat は 64 ビット環境専用です。

詳細エラーの直前値はスレッドごとに独立しています。  
別のスレッドから参照することはできません。

直前値は、次に詳細エラーを扱う機能を使用すると上書きされます。  
保持が必要な場合は、利用側が取得直後に複製する必要があります。

結果と共通の原因に割り当てた既存の値は変更できません。
